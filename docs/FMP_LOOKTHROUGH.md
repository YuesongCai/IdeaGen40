# 穿透层：ETF 到底持有什么

## 为什么加这条腿

四个数据源里，Futu 给价格，Olive 给货架，Wisburg 给论据，**没有一个能说出一只 ETF 实际持有什么**。
所以 `universe.py` 用一条手写的 `exposure` 标签描述一只标的，`_gen.universe_block()` 把这些标签
拼成菜单交给模型选。那条函数的注释本来就写着它要修的病——没有标签时"模型是在匹配 ticker 字符串"。

**标签修好了 ticker 匹配，没修好标签匹配。** 它是一个人手打的一句话，所以被它写成同一句话的产品，
在生成器眼里就是可互换的行，无论它们实际怎么造的。2026-09-05 用真持仓量过：

| 现象 | 证据 |
|---|---|
| 标签相同、底层不同 | ITA / PPA / XAR 都写「国防军工」，对同一批十家军工主承包商的权重是 **53.7% / 45.0% / 26.1%** |
| 同上 | USMV / SPLV 都写「美股低波动」，按权重只重叠 **27%** |
| 标签不同、底层相同 | VLUE 写「美股价值因子」，底层 **21% 是半导体**。用 SMH 做多半导体、再用 VLUE 做价值对冲，五分之一的对冲是同一笔注 |
| 名字找不到的敞口 | 「AI 电力 / 数据中心」权重最高的是 **GRID**（标签「智能电网与电气化」），按名字匹配够不到；**IYR**（美国房地产）通过 DLR+EQIX 给 9.2% |

## 三件事

### ① 反向映射（你要的那条路）

主题先有公司名，才有产品。`resolve_theme()` 把一份底层名单，换成一张**按真实权重排序**的可交易标的表。

```bash
ideagen lookthrough theme --names LMT,RTX,NOC,GD,LHX,BA,HII,LDOS,TDG,HWM
```

排序按**穿透权重**，不是按命中个数——十家军工里持有九家、每家 0.2%，那不是一个军工仓位。

### ② 真实集中度

十只 ETF 不等于十笔注。`portfolio()` 报的是**底层这一层**的有效名数。

```bash
ideagen lookthrough portfolio --symbols SMH,SOXX,QQQ,QUAL,MTUM
```

这条正对着回测里 `robustness_drop_top` 的发现：剔掉二十个标的优势就归零，
说明那个优势从来没有分散在持有它们的产品上。这个数在**下单前**就能算，
而不是等一个月之后回测告诉你。

### ③ 覆盖率下限

期货型和实物型基金的持仓行没有任何标识符。天真地读，DBC 和 PDBC——两只宽基商品——
重叠 0%，这比没有答案更糟。所以每个答案都带它认出了多少净值，
低于 `MIN_COVERAGE`（0.60）的比较返回 `None` 而不是一个数字。

**覆盖率必须按「非现金、非衍生品」算，这一条是被一个假发现逼出来的。**
第一版按毛覆盖率算，于是：

- FXY / FXE / UUP 报「100% 可穿透」，非现金持仓 **0%**——货币 ETF 的敞口是 JPY / EUR / USD，
  根本不在持仓名单这个空间里。`differentiator` 老老实实印出了「前0大（合计 0%）」。
- **DBMF vs KMLM 重叠 0%，标签同为「跨资产趋势策略」**——看起来正是本文要找的那种证据，
  而它是假的。KMLM 五只持仓全是 `US912797…`（美国国库券的 CUSIP 前缀），
  标签写作 `B 09/29/26`，字面上没有任何一个字说"现金"；它真正的敞口（KFA MLM 指数期货）
  一行都没报。DBMF 那四行是 CBT 期货合约，而**期货的权重是名义本金、不是净值占比**，
  跟股票权重相加是范畴错误。

两条规则因此按**标识符**而不是按名称判断：`912797` 前缀判国库券抵押品，
合约描述里的 CBT / CME / NYMEX / CURR FUT 判衍生品。修完这两只双双落到下限之下，
那条"发现"被撤回。**教训：一个看起来正好印证你论点的数字，是最该去查的那个。**

**这条本身就是信号**：ev_rank 那条组合在 07-29 期只有 54% 可穿透，
剩下的是 COPX / USO / CPER 这批商品期货 ETF——正好是记忆里
「优势集中在少数高波动标的」指认的同一批名字。**排名最好的组合，也是最看不透的组合。**

## 主键是 ISIN，不是 ticker

显而易见的键是 `asset` ticker，而它错在两处：

- **债券基金整列为空**。TLT 全部 49 行、LQD 全部持仓的 `asset` 都是空字符串。按它做键，
  这个 universe 里整个利率和信用的一半会被判成"看不透"。
- **同一家公司在不同基金里是不同字符串**。美国基金里是 ASML，欧洲基金里是 ASML.AS，
  按 ticker 算会静默低估两只基金的重叠。

`isin` 在这批数据里覆盖 **98.5%** 的加权持仓行（含债券），且按定义一只证券一个。
所以它是键，ticker 和厂商描述只留作显示。之后仍未识别的，是**源头就没有标识符**的：
期货和实物行没有 ISIN、没有 CUSIP、也没有 ticker。

## 数据源

Financial Modeling Prep，只用 `/stable` 树。

**legacy `/api/v3` 和 `/api/v4` 已对 2025-08-31 之后签发的 key 关闭**，
而且是以 HTTP 200 + `{"Error Message": ...}` 的形状返回——最容易被当成数据的那种失败。
`fmp._get()` 因此把 `Error Message` 当错误抛，即使传输层成功。

2026-09-05 在这把 key 上实测通过：`etf/holdings`、`etf/asset-exposure`、
`etf/sector-weightings`、`etf/country-weightings`、`quote`、`historical-price-eod/full`、
`etf-list`、`profile`、`company-screener`、`ratios`、`key-metrics`、`sp500-constituent`。

实测**不可用**：`etf/info`（空）、`search-symbol`（对主题几乎无用——查 "quality"
返回一只印度共同基金，正是这个模块要替换掉的按名字匹配，只是从厂商那一侧来的）。

凭证放 `~/.ideagen.env`（0600，仓库外）：`FMP_API_KEY=...`。

## 命令

```bash
ideagen lookthrough refresh                  # 拉全部 US 标的持仓，约 90 秒
ideagen lookthrough collisions               # 现有标签在哪里说了谎
ideagen lookthrough theme --names A,B,C      # 主题名单 → 该买哪只
ideagen lookthrough portfolio --symbols A,B  # 一组持仓真实押在什么上
```

`refresh` 并发拉取：厂商延迟随持仓行数走（SPY 三秒，IWM 两千行二十二秒），
串行扫一遍这个 universe 要一刻钟。取数失败的标的**存成带原因的 run 行而不是略过**——
缺行和失败行对后面每一个查询都长得一样，那正是这个仓库在 Olive 那条腿上遇到过的
"静默降级成什么都不产、同时报告成功"。

## 第五种生成方式：穿透反查（2026-09-05 开）

`ideagen/strategies/gen_lookthrough.py`，注册名 `lookthrough`，
role **exploratory**，面板标签「穿透反查」。

其余四种生成方式在「怎么推理」上不同，在「怎么挑标的」上**完全一样**——
读那张标签菜单，挑一行听起来像的。那一步根本不是推理方法，是查表。
这一种把决定沿着两种能力真正的分界线切开：

> **模型说出公司，持仓数据说出标的。**

1. 给主题、打分A 依据和研报，模型列出论点真正指向的**上市公司**（语义活，模型擅长）；
2. `resolve_theme()` 用真实持仓算出每只可买标的有多少净值压在这批公司上（算术活，不需要模型）；
3. 模型在这张**带实测权重**的候选表里写想法，看到的是「ITA 该主题真实穿透权重 53.8%，
   其中持有 RTX、BA、GD…」，不是「国防军工」四个字。

实测（2026-09-05 快照，91 只可买）：

| 主题 | 候选数 | 第一名 |
|---|---|---|
| AI 电力 / 数据中心 | 7 | GRID 19.9%（标签是「智能电网与电气化」） |
| 欧洲重整军备 | 4 | ITA 53.8% ＞ PPA 45.0% ＞ XAR 26.1% |
| 黄金避险 | **0，拒绝** | 「名单 NEM、AEM、GOLD… 没有任何标的的穿透权重达到 3%」 |

**两条代价，写在前面：**

**每个主题两次模型调用而不是一次。** 老实计数——`build_prompt` 把第一段的调用次数
作为第三个返回值交回 `generate_per_topic` 计入 `calls`。
一种成本翻倍却报单倍的方法，会正好在比成本的那一列里显得最便宜。

**它表达不了所有主题，而且它会说出来而不是装作能。** 黄金 / 汇率 / 管理期货的论点
没有可识别证券构成的名单，覆盖率下限会拒绝给它们打分。这时这一种生成方式**抛错、
不产出**，`generate_per_topic` 记成该主题的 `topic_errors`。

**退回标签菜单比不产出更糟。** 这里要量的就是「按持仓挑标的是否胜过按标签挑」，
一种在难题上悄悄退回标签的方法，看起来回答了这个问题，实际回答的是另一个。
在一部分主题上候选更少，是这个方法的真实属性；被污染的对比事后救不回来。

按 **exploratory** 注册，和 ev_rank 同样待遇、同样理由：机制是在看过它将被评判的
数据之后才设计的，**只有它往后的 live 期次算证据**。

### 快照陈旧度由这一种生成方式自己拦

策略层**不能联网**——`RunContext` 故意不给数据库句柄和网络，
「能查询的策略就是能不小心读到未来的策略」。所以过期的快照只能在这里**拒绝**，
不能在这里**修复**。超过 `MAX_SNAPSHOT_AGE_DAYS`（21 天）就抛错并报出快照日期。

刷新已接进日更：`ideagen daily` 的 `[3/9] ETF 穿透快照`。
持仓按基金自己的再平衡节奏动、不是每天动，所以这是便宜的保险而不是实时源；
失败会被 `stage()` 记下来但不会拖垮整个 daily。

## 货架外发现

`ideagen lookthrough discover --names ...`

`resolve_theme` 回答「我们这 95 只里哪只表达这个主题」；当答案是「一只都没有」时，
**那是关于货架的事实，不是关于主题的事实**，而这两件事极易混淆。
黄金矿业的论点在这里得零分，不是因为没有载体，
而是因为货架上只有实物 GLD、没有金矿股基金——**一个标签菜单永远发现不了的策展缺口，
因为缺口没有标签**。

实测：`--names NEM,AEM,GOLD,FNV,WPM` 反查出 **GDX 31.8%**（VanEck 金矿股，正确答案）。

它走的是反向索引而不是本地矩阵，这是故意的：本地矩阵只认识货架，
所以它永远说不出货架缺什么。代价是每个名字一次厂商调用，
所以这是一条**手动命令**、不进周跑。

返回的是候选、不是结论：进 universe 要确认载体合规、日度申赎、以及 Futu 能不能报价——
持仓文件这三件事一件都答不了。

## 菜单开关与断点

`IDEAGEN_UNIVERSE_LOOKTHROUGH=1` 让 `universe_block` 的每一行多带它最大的实际持仓：

```
ITA  | iShares US Aerospace & Defense | 国防军工   | ETF | 前4大 GE 22%、RTX 17%、BA 9%、GD 5%（合计 53%）
XAR  | SPDR S&P Aerospace & Defense   | 国防军工   | ETF | 前4大 AXON 3%、VSEC 3%、ACHR 3%、RTX 3%（合计 13%）
AGG  | iShares Core US Aggregate Bond | 美国综合债 | ETF | 13298 只成分高度分散，前4大合计仅 1.6%
GLD  | SPDR Gold Shares               | 黄金       | ETF | 不可穿透（opaque，认出 0%）
```

**名字只对集中的基金有区分度。** 第一版对每只基金都印前四大，于是 LQD 印出
`前4大 ANHEUSER-BUSCH COMPANIES LLC 4.90% 02/01/2046 0%…`——零信息量，
而且是整张菜单最长的一行。低于 `FLAT_BELOW`（前四大合计 10%）时改成报它自己的**平坦度**，
那才是区分它的事实：ITA 是两个头寸，XAR 是一百个等权头寸，说清这一点比列四个 3% 的代码有用。
菜单开销因此从 +128% 降到 **+87%**（4,231 → 7,910 字符）。这张菜单是每次调用都要付的钱。

**每一次运行都会把自己站在断点哪一侧记进元数据**（`meta.universe_lookthrough`）。
这不是记录癖：这个开关改的是模型看到的东西，所以开关两侧的期次彼此不可比，
而这个事实能活过一年的唯一地方，是那次运行自己的元数据——不是某份文档里的一句话。
开着的时候五种生成方式改动完全一致，所以**它们相互之间仍然可比，只是和自己的历史不可比**。

## 还没做的决定（需要你拍板）

**开关什么时候打开。** 决定已经做了（下一个完整周期开头），
但打开它是一次生产行为变更：`~/.ideagen.env` 里加一行
`IDEAGEN_UNIVERSE_LOOKTHROUGH=1`。本机是 09-09 那期的 runner
（见周三预演的定案），所以改本机这一处就是完整的改动，不会造成两台菜单不一致。

**扩不扩货架。** `discover` 已经指出了第一个缺口（金矿股，GDX 31.8%）。
扩货架要过流动性、申赎和 Futu 报价三关，属于研究 + 运营决定。
