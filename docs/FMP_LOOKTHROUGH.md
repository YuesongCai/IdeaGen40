# 穿透层：ETF 到底持有什么

## 为什么加这条腿

四个数据源里，Futu 给价格，Olive 给货架，Wisburg 给论据，**没有一个能说出一只 ETF 实际持有什么**。
所以 `universe.py` 用一条手写的 `exposure` 标签描述一只标的，`_gen.universe_block()` 把这些标签
拼成菜单交给模型选。那条函数的注释本来就写着它要修的病——没有标签时"模型是在匹配 ticker 字符串"。

**标签修好了 ticker 匹配，没修好标签匹配。** 它是一个人手打的一句话，所以被它写成同一句话的产品，
在生成器眼里就是可互换的行，无论它们实际怎么造的。2026-09-05 用真持仓量过：

| 现象 | 证据 |
|---|---|
| 标签相同、底层不同 | ITA / PPA / XAR 都写「国防军工」，对同一批十家军工主承包商的权重是 **53.7% / 45.0% / 26.1%** |
| 同上 | USMV / SPLV 都写「美股低波动」，按权重只重叠 **27%** |
| 标签不同、底层相同 | VLUE 写「美股价值因子」，底层 **21% 是半导体**。用 SMH 做多半导体、再用 VLUE 做价值对冲，五分之一的对冲是同一笔注 |
| 名字找不到的敞口 | 「AI 电力 / 数据中心」权重最高的是 **GRID**（标签「智能电网与电气化」），按名字匹配够不到；**IYR**（美国房地产）通过 DLR+EQIX 给 9.2% |

## 三件事

### ① 反向映射（你要的那条路）

主题先有公司名，才有产品。`resolve_theme()` 把一份底层名单，换成一张**按真实权重排序**的可交易标的表。

```bash
ideagen lookthrough theme --names LMT,RTX,NOC,GD,LHX,BA,HII,LDOS,TDG,HWM
```

排序按**穿透权重**，不是按命中个数——十家军工里持有九家、每家 0.2%，那不是一个军工仓位。

### ② 真实集中度

十只 ETF 不等于十笔注。`portfolio()` 报的是**底层这一层**的有效名数。

```bash
ideagen lookthrough portfolio --symbols SMH,SOXX,QQQ,QUAL,MTUM
```

这条正对着回测里 `robustness_drop_top` 的发现：剔掉二十个标的优势就归零，
说明那个优势从来没有分散在持有它们的产品上。这个数在**下单前**就能算，
而不是等一个月之后回测告诉你。

### ③ 覆盖率下限

期货型和实物型基金的持仓行没有任何标识符。天真地读，DBC 和 PDBC——两只宽基商品——
重叠 0%，这比没有答案更糟。所以每个答案都带它认出了多少净值，
低于 `MIN_COVERAGE`（0.60）的比较返回 `None` 而不是一个数字。

**覆盖率必须按「非现金、非衍生品」算，这一条是被一个假发现逼出来的。**
第一版按毛覆盖率算，于是：

- FXY / FXE / UUP 报「100% 可穿透」，非现金持仓 **0%**——货币 ETF 的敞口是 JPY / EUR / USD，
  根本不在持仓名单这个空间里。`differentiator` 老老实实印出了「前0大（合计 0%）」。
- **DBMF vs KMLM 重叠 0%，标签同为「跨资产趋势策略」**——看起来正是本文要找的那种证据，
  而它是假的。KMLM 五只持仓全是 `US912797…`（美国国库券的 CUSIP 前缀），
  标签写作 `B 09/29/26`，字面上没有任何一个字说"现金"；它真正的敞口（KFA MLM 指数期货）
  一行都没报。DBMF 那四行是 CBT 期货合约，而**期货的权重是名义本金、不是净值占比**，
  跟股票权重相加是范畴错误。

两条规则因此按**标识符**而不是按名称判断：`912797` 前缀判国库券抵押品，
合约描述里的 CBT / CME / NYMEX / CURR FUT 判衍生品。修完这两只双双落到下限之下，
那条"发现"被撤回。**教训：一个看起来正好印证你论点的数字，是最该去查的那个。**

**这条本身就是信号**：ev_rank 那条组合在 07-29 期只有 54% 可穿透，
剩下的是 COPX / USO / CPER 这批商品期货 ETF——正好是记忆里
「优势集中在少数高波动标的」指认的同一批名字。**排名最好的组合，也是最看不透的组合。**

## 主键是 ISIN，不是 ticker

显而易见的键是 `asset` ticker，而它错在两处：

- **债券基金整列为空**。TLT 全部 49 行、LQD 全部持仓的 `asset` 都是空字符串。按它做键，
  这个 universe 里整个利率和信用的一半会被判成"看不透"。
- **同一家公司在不同基金里是不同字符串**。美国基金里是 ASML，欧洲基金里是 ASML.AS，
  按 ticker 算会静默低估两只基金的重叠。

`isin` 在这批数据里覆盖 **98.5%** 的加权持仓行（含债券），且按定义一只证券一个。
所以它是键，ticker 和厂商描述只留作显示。之后仍未识别的，是**源头就没有标识符**的：
期货和实物行没有 ISIN、没有 CUSIP、也没有 ticker。

## 数据源

Financial Modeling Prep，只用 `/stable` 树。

**legacy `/api/v3` 和 `/api/v4` 已对 2025-08-31 之后签发的 key 关闭**，
而且是以 HTTP 200 + `{"Error Message": ...}` 的形状返回——最容易被当成数据的那种失败。
`fmp._get()` 因此把 `Error Message` 当错误抛，即使传输层成功。

2026-09-05 在这把 key 上实测通过：`etf/holdings`、`etf/asset-exposure`、
`etf/sector-weightings`、`etf/country-weightings`、`quote`、`historical-price-eod/full`、
`etf-list`、`profile`、`company-screener`、`ratios`、`key-metrics`、`sp500-constituent`。

实测**不可用**：`etf/info`（空）、`search-symbol`（对主题几乎无用——查 "quality"
返回一只印度共同基金，正是这个模块要替换掉的按名字匹配，只是从厂商那一侧来的）。

凭证放 `~/.ideagen.env`（0600，仓库外）：`FMP_API_KEY=...`。

## 命令

```bash
ideagen lookthrough refresh                  # 拉全部 US 标的持仓，约 90 秒
ideagen lookthrough collisions               # 现有标签在哪里说了谎
ideagen lookthrough theme --names A,B,C      # 主题名单 → 该买哪只
ideagen lookthrough portfolio --symbols A,B  # 一组持仓真实押在什么上
```

`refresh` 并发拉取：厂商延迟随持仓行数走（SPY 三秒，IWM 两千行二十二秒），
串行扫一遍这个 universe 要一刻钟。取数失败的标的**存成带原因的 run 行而不是略过**——
缺行和失败行对后面每一个查询都长得一样，那正是这个仓库在 Olive 那条腿上遇到过的
"静默降级成什么都不产、同时报告成功"。

## 还没做的决定（需要你拍板）

**1. 要不要把穿透喂进生成器菜单。** `IDEAGEN_UNIVERSE_LOOKTHROUGH=1` 会让
`universe_block` 的每一行多带它最大的实际持仓。**默认关**，因为这是送进模型的输入：
中途打开意味着后面的期次和前面的期次是对着不同的菜单生成的。打开时四种生成方式
改动完全一致，所以臂之间仍然可比——但和它们自己的历史不可比。

**2. 要不要开第五种生成方式。** 「模型说出主题的公司名单 → 穿透反查出标的」
是一条完整的生成路径，且比现在的按标签挑更贴初心（语义分析负责语义，数据负责映射）。
加一条臂是**新增一列**、不动现有四列，实验设计上是干净的。但按初心，
生成方式的增减是研究决定，不是工程决定。

**3. shelf 之外的发现。** `etf/asset-exposure` 能反查出 universe 之外的产品。
现在 95 个标的是人工策展的，穿透能指出"这个主题在货架上没有好载体"，
并给出货架外的候选。是否要据此扩货架，同样是研究决定。
