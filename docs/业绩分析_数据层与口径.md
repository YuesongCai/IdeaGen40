## 1. 三套数据的边界

### 1.1 模拟运行 vs 历史回测

`paper_view` 只读 `books` 里 `sel-` 前缀的组合（并显式排除 `bt:`）；`backtest_view` 只读
`backtest_*` 三张表，正式回测的分解与归因从它自己保留的 `bt:` 组合记录读，**不读** `sel-`。
测试 `test_paper_view_never_reads_a_backtest_book` / `test_backtest_view_is_built_from_backtest_tables_only`
各钉一边。

### 1.2 模拟运行内部：按时 vs 补跑

每个仓位的分类沿存储 id 走：`positions.idea_uid → ideas.batch_id → batches.generator`
（形如 `weekly:<run_id>`）`→ orch_runs.data_classification`。库里的取值只有 `NULL`（按时）
与 `'backfill'`。走不通的记 `unknown`，不进任何子集，`reason` 里报数量。

真实库：**十个组合里只有 08-26 一期是按时跑出的**，07-29 / 08-05 / 08-12 / 08-19 / 09-02 五期
都是 09-04 补跑的；`generated_ai_native` / `generated_carl_constraint` 两个组合在按时子集里
**一个仓位都没有**（它们只在补跑期出现），所以在默认视图里是「缺数据」，不是一条 0% 的线。

### 1.3 为什么补跑必须重建而不能删行

同一个组合的现金与利息是连续的。补跑的五期在 09-04 一天里买入，当天按到期平掉，
它们的成交现金流和之后每天的利息都混在账上。把它们的行藏掉，剩下的净值对不上账。

所以 `subset=live` 的口径：

1. 从资本 10,000,000 起步；
2. 只重放该子集仓位的 BUY / SELL 现金流（`trades.cash_delta`）；
3. 在账上**记过 INT 的每个交易日**、按**当天记录的同一利率**（从 INT 的 `reason` 里
   `MM yield x.xxx%` 解析，货架中位数或兜底常数都照原样）、对重建后的**前一交易日**现金
   余额重算利息——`paper._accrue_cash` 同一公式；
4. 市值取该子集仓位的逐日 `mtm.mv`；
5. 净值 = 现金 + 市值。

`subset=backfill` 对称；`subset=all` 直接读 `equity` 表。三者各自的周 PnL、汇总、归因。

## 2. 自然周 × 策略 PnL：分解与对账

ISO 周分桶。每周：`equity_start` = 上一盯市日净值（首周 = 资本）；`equity_end` = 周内最后
盯市日净值；`pnl_amt = equity_end − equity_start`；`pnl_pct = pnl_amt / equity_start`。

分解恒等式（每一项都**扣费前**，费用单列）：

```
pnl_amt = realized + unrealized_chg + cash_income + fees + flows
realized       = Σ(平仓毛收入 − 毛成本)            周内平掉的仓位
unrealized_chg = U(周末) − U(周初)，U = Σ(市值 − 毛成本)  周末/周初在手的仓位
cash_income    = Σ INT                              货币基金利息
fees           = −Σ(建仓费 + 平仓费)                周内付的
flows          = 0                                  出入金（今天没有，字段留着）
```

`residual` 是差额，`reconciled` 只在 |residual| ≤ 0.05 美元时为真。真实库三个子集
共 6 周 × 10 组合，**全部对账**（residual 为 0）。正式回测保留的 `bt:` 组合同样全部对账。

**不混进来的东西**：「某批 ideas 生成后未来一个月的回报」——那是批次分析，不是本周账户盈亏。

选股研究只有指数化净值点（起点 100），没有资金账：`pnl_amt` 是真实的净值变化，分解项
填 0，`reconciled=false` 表示「无法对账」，`decomposition: "not_recorded"` 说明原因。

## 3. 汇总表定义

| 列 | 定义 |
|---|---|
| `cum_ret_pct` | 期末净值 / 资本 − 1（正式回测同）；选股研究 = 末点 / 首点 − 1 |
| `excess_spy_pp` | `cum_ret_pct` − SPY **同一起止日**的累计收益（百分点）；起止日 SPY 缺价则 null 并写 reason |
| `excess_buy_all_pp` | 同上，对 `sel-buy_all` 组合（同一子集、同一账规则）；buy_all 自己为 null |
| `max_dd_pct` | `perf.drawdowns` 最深一段 |
| `cash_share_end_pct` / `cash_share_avg_pct` | 现金 / 净值，期末值与期间逐日平均**都给**；`cash_share_basis: "end"` 说明表头主用期末 |
| `n_periods` | 该组合在该子集里出过手的期数（`COUNT DISTINCT positions.as_of`） |
| `n_days` | 盯市交易日数（曲线点数 − 1，种子行不算） |
| `status` / `reason` | `ok` / `缺数据`（组合在、子集里没仓位）/ `未运行`（注册表有、`books` 表无）/ `失败` |

`roster_diff`：对照另一模式的名单。**缺席原因只写记录里有的**——依次查
`summary.excluded_reasons[arm]`、`summary.skipped_need_model`、`summary.excluded_arms` +
disclaimer 里「未参与：…」那句；都没有就 `null`。真实库：ai_native 缺席选股研究的原因来自
disclaimer（「需调用模型，会使复算不可重复」）；ev_rank / mom_21 缺席模拟运行的原因是
`books` 表里没有它们的组合（记录本身）。

全量基准缺期要点名：真实库 buy_all 缺 08-12、08-19 两期（`W20260812-buy_all` /
`W20260819-buy_all` 校验未过：`ref_price_present` / `ref_price_dated`），`benchmarks.buy_all.reason`
把批次号和卡住的检查一起写出来。

## 4. 归因规则

仓位损益 = 已平仓 `realized`（扣费后）+ 未平仓最新 `mtm.upnl`；不含现金利息。

来源沿 持仓 → 想法 → 候选 追溯：主题取候选 payload 的 `topics` 列表（多主题完整保留），
方法取 `sources[].methods` ∪ payload `proposed_by`；追不到的记「来源未记录」。

- `pnl_full_credit`：一个标的的全部损益完整计入它的**每一个**来源。多来源标的在每个来源
  下各出现一次，各行**不可相加**，是观察视图。
- `pnl_split_equal`：按来源数均分，各行可相加，**合计 = 该子集总交易损益**。

测试 `test_split_equal_adds_up_and_full_credit_does_not` 用一个双主题双方法的标的钉住：
split 之和 = 总额，full 之和 = 总额 + 该标的损益。

选股研究没有资金账，归因单位是**百分点之和**（`unit: "pct_points"`），`rule` 里写明。

## 5. 正式回测：与模拟运行的规则对照

`ideagen/backtest_formal.py`。不另写引擎：每个成功周跑的每个选取策略，把它当时选中的候选
经 `booking.payload_from_candidates → ideas.build_batch` 建成批次
`BT-<backtest_id>-W<date>-<arm>`，下到 `bt:<backtest_id>:<arm>` 组合，然后按期次顺序交错地
`paper.step`（开这一期的批次 → 走到下一期前一天 → 开下一期）。交错是必须的：`size_batch`
按当天现金定额，只有前几个 tranche 已经盯市到当天，这个数才对。

| 环节 | 模拟运行 | 正式回测 | 一致？ |
|---|---|---|---|
| 候选与判决 | 周跑的 verdicts / candidates | 同一份，不重跑选取 | ✓ |
| 当日无价的标的 | `booking._priced_only` 剔除 | 同一函数 | ✓ |
| 批次校验 | `ideas.validate_batch` | 同一函数（价格若已补齐会建仓，仍缺则跳过并记录） | ✓ |
| 分批资金 | 每期 tranche = 25% 资本，不超现金 | 同一段 `size_batch` | ✓ |
| 仓位分配 | 期内等权 | 同 | ✓ |
| 成交 | 收盘市价，5 个交易日订单寿命 | 同一段 `_try_fill` | ✓ |
| 成本 | 两腿各计（佣金+滑点）/2 | 同一段 `_apply_fill` / `_close_position` | ✓ |
| 止损 / 止盈 | σ×2 / σ×3，建仓时固定 | 同一段 `booking._fix_stops` + `paper.step` | ✓ |
| 到期退出 | `horizon_end` | 同 | ✓ |
| 现金利息 | 前一日现金 × 年化 × 天/365 | 同一段 `_accrue_cash` | ✓（利率取运行时的值） |
| **下单时点** | 真实生成时刻（补跑期都是 09-04） | **钳制到该期日期 07:23 HKT**（`backtest.GENERATION_TIME`） | ✗ 披露 |
| **事件退出** | 依赖实时 alerts | 回测组合没有 alerts，**永不触发** | ✗ 披露 |
| **价格** | 逐日按当时行情 | 今天的 `prices` 表整段回放 | ✗ 披露 |
| 上架日期过滤 | 无 | 无 | ✓（都没有） |

差异写在 `backtest_formal.DISCLOSURES`，随每次运行存进 `backtest_runs.summary.disclosures`，
`backtest_view` 原样交给页面。

隔离：`config.BACKTEST_BOOK_PREFIX = "bt:"`，`paper.book_spec` 对它返回 `SELECTOR_SPEC`，
`paper.all_books` **显式排除**（日常盯市循环碰不到，`test_run_creates_isolated_books_and_batches`
钉住）。同一 `backtest_id` 重跑先 `cleanup` 再建，幂等（`test_rerun_is_idempotent`）。
跑完 `bt:` 组合**保留**，因为周 PnL 分解与归因要从它读；清理了就只剩净值点。

命令：`ideagen backtest-formal [--from D --to D] [--arms a,b] [--backtest-id X] [--dry-run]`。

## 7. API 与索引

- `GET /api/perf?mode=paper|backtest&subset=live|backfill|all&source=<backtest_id>` → `PerfView`。
  非法 `mode` / `subset` 返回 400 并说明；视图构建异常返回 500 带类型与消息。按需拉，不进轮询。
- `review.state()["perf_index"]`：两个模式的可用性、窗口、组合数、methodology、source_id，
  加 `live` 占位与 `backtest_sources`（可选的全部回测 id，最新在前）。只查计数，不构建曲线。
  `live.label` 写成「实盘（未接入）」而不是契约里的「实盘」：`tests/test_glossary.py` 的词表闸门
  只允许「实盘」出现在否定里（这套系统的实盘通道是故意没有接的），标签本身把否定带上。

契约相对约定**新增**了这些字段（没有改名、没有删）：顶层 `subset_label`、`methodology_raw`
（回测）；策略行 `book_id`；`benchmarks.spy.code`、`benchmarks.buy_all.missing_periods`；
周行 `first_d`、`last_d`、`decomposition`（回测点只有净值时）；`roster_diff.other_source_id`；
`attribution.unit`、`attribution.total_pnl`；`records.period_classification`、`records.backtest`、
`failed_runs[].resolved`；`research.extra`（回测记录里的 paired / prereg / ranking_power 等）；
`perf_index.backtest_sources`、`modes[].subsets`、`modes[].default_subset`。

## 8. 局限与待验证

1. **按时子集只有一期。** 十个组合里 08-26 是唯一按时跑出的；默认视图的每一列都是一期的
   读数，表头 `n_periods=1` 是它唯一诚实的说明。要到 10 月才有四期。
2. **重建口径里的利率**来自账上每天 INT 的 `reason` 解析；没有 INT 的日子（种子行）不计息，
   与引擎一致。若将来 INT 记录格式变了，`_rate_on` 退回 `RISK_FREE_ANNUAL` 并且**不会报错**——
   这是一处「绿着的失败」候选，测试 `test_live_interest_is_recomputed_on_the_rebuilt_balance`
   只钉住了当前格式。
3. **正式回测的止损从未触发。** 6 期 1,168 条持仓一次止损都没有，而止盈 28 次。σ×2 的止损
   在这段上涨里没被考到，不能据此说止损规则「有效」或「无效」。
4. **事件退出在正式回测里永不触发**（无 alerts）。模拟运行里目前也没有触发过（alerts 表里
   `thesis_invalidated` 为 0 条），所以今天两边一致，但机制上不一致，已披露。
5. **正式回测写的是本地 SQLite。** 云端 MySQL 状态库走的是 `cloud_paper` 那条路，本引擎没有接。
6. **同日多批次透支**（§6.3）是 `paper.open_batch` 的问题，本层只报不修。
7. **研究检验块**复用 `perf.compare_arms`，样本 27 天时每个区间都盖住 0；`sample_note` 写了，
   但页面若把它放在首屏就会被当结论读。
8. **`stuck_batches` 的算法**在 `review.state` 与 `performance.stuck_batches` 各有一份
