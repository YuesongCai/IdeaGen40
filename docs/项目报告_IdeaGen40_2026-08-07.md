## 1. 背景与目的

原来的流程是：读智堡日报 → 按《战术宏观主题评分框架 v0.3》打分 → 挑出主题 →
按《战术 Trade Idea 排名方法论 v0.3》展开成 40 条交易想法 → 出一版 HTML + 计算底稿。

这个流程每次都能产出 40 条看起来很完整的想法，但**从来没有人回答过一个问题：
这些想法如果真的买下去，会怎么样。**

原因不是没人想问，而是流程本身让这个问题无法回答：

- **从不记录结果。** 打完分、出完 HTML，下一版重新来一遍。没有任何一条 idea
  被跟到期限结束，所以「A 级比 C 级好」这种主张既无法证实也无法证伪。
- **概率是不可伪证的。** 情景概率和回报可以是纯 `research_judgment`，
  于是任何结局都与预测相容——涨了是「上涨情景兑现」，跌了是「下跌情景兑现」。
- **没有成本、没有执行规则。** 「$73–76 分两笔」在纸面上很清楚，
  但没人定义过它到底算不算成交、成交在哪个价、算不算滑点。

所以这个项目要做的是：**把这套流程变成一个每天真的下单、真的盯市、
真的记结果的系统**，让「40 条 idea 值不值钱」变成一个有答案的问题。

具体要回答三件事：

1. 这些 idea 的**方向**对不对？（等权收益、胜率、超额）
2. 引擎给出的**排序**有没有信息？（赔率 vs 实际收益的 Spearman ρ）
3. 它声明的**概率**诚不诚实？（三分类 Brier 与技能分）

**这不是策略回测。** 它不问「这个策略能不能赚钱」，
而问「这套研究流程产出的判断，事后被市场证明对了多少」。

## 2. 方法论：v0.3 有什么问题，v0.4 怎么改

先说结论：**v0.3 的问题不是想错了，而是很多规则在它自己的数据口径下
根本无法被执行、或者无法被检验。**

这一点在 7/28 那份《来源口径诊断》里已经点出了一半——那份诊断是对的，
而且推导可复算。v0.4 把它的四条建议全部实现，并另外发现了 10 处问题。

### 2.1 最要紧的六项改动

**① D 和 A 是退化的查表，不是连续变量。**

v0.3：`D = 100 × 提及主题的独立日报数 ÷ 窗口有效日报总数`，
核心来源是每天一份的智堡首页日报，3 日窗口 → 分母恒为 3。

- D 只有 4 个取值：0 / 33.3 / 66.7 / 100
- A 穷举全部 8 种组合后只有 5 个取值：0 / 25 / 50 / 75 / 100
- 而且 `(1,0,1)` 与 `(1,1,1)` **同为 50 分**——恰好抹掉了 A 存在的理由
  （「持续讨论」和「首尾各提一次」不可区分）
- `minimum_valid_reports: 5` 在 3 日窗口下**永远无法满足**，每轮都被标记低置信

合计 **40% 的权重坐在一个 4×5 = 20 格的表上。**

v0.4：把计票池换成 **8 条线的来源条目**。3 日窗口实测 1,632 条，
其中 D/A 的计票池（Tier2 卖方 + Tier3 策展）1,105 条。
A 保留重心项（保持可比），再混入**强度项**：
当日份额在该主题自身过去 20 天分布中的百分位。

实测效果（2026-08-06 那天）：D 跨主题从 46 到 100，A 从 25 到 63，
B 从 3.5 到 68.6，N 从 69 到 97.5 —— 全部连续、可区分。

**② N 里权重最大的子项长期是 NA。**

「意外程度」（占 N 的 40%）要求 `|实际−一致预期| ÷ 过去两年同类预测误差标准差`。
语料里几乎从不同时给出实际值、一致预期和历史预测误差分布。
按 §12「任一因子缺失时按剩余权重归一化」，结果是：
**占总分 35% 的最大因子，长期在缺掉自己 40% 权重的状态下运行。**

v0.4：改用**可观测代理**——主题预注册价格指标在窗口内的最大单日涨跌幅
÷ 自身 60 日日波动。分档表沿用 v0.3（z<0.5→20 … ≥2→100）。
每天都算得出来。语料若真给出 actual-vs-consensus，则覆盖代理值。

**③ 情景不可伪证。**

v0.4 要求上下行幅度落在标的自身已实现波动的 `[0.35σ, 2.60σ]` 内：

```
σ_h    = 标的已实现年化波动 × √(月数/12)
k_up   = |R_up|   ÷ σ_h ,  k_down = |R_down| ÷ σ_h
```

一个月期的想法不能写「+30% 上涨」而标的月波动只有 4%（k=7.5，属于幻想），
也不能写「+0.5%」（k=0.12，属于没有观点）。
超出就标 `narrow` / `wide`，不否决，但写进 outcome 供事后检验。

**④ 不计成本。**

v0.3 全文没有提到佣金、滑点、借券。v0.4 双边计入
（美股往返 0.08%，港股 0.15%），**在算赔率之前**从三个情景回报里扣掉。
一条边比自己价差还薄的 idea 不会再评成好赔率。

**⑤ 没有拥挤度。**

v0.3 里一个主题可以 TIS 90 分，而它的表达工具正处在 1 年动量极值，模型不会反对。
新增独立因子 **C**：

```
C = 0.45 × 60日动量百分位
  + 0.30 × 距52周高点得分
  + 0.25 × (100 − 20日波动百分位)     ← 高位且安静才最拥挤
```

C ≥ 80 强制「等待回踩」并把仓位减半。
实测当天 USMV 的 60 日动量百分位是 **100.0**（一年最高），
系统已就此发出 `crowding_spike` 告警。

**⑥ 从不记录结果。**

v0.4 为每条 idea 落一条 outcome，**包括从未成交的那些的反事实收益**，
然后输出排序 ρ、Brier 校准与技能分、以及按评级/期限/主题/拥挤度/幅度校验的分档。

### 2.2 另外八项

| 问题 | 修法 |
|---|---|
| 「同一机构只计一次」无法执行——语料没有机构字段 | 从正文抽取 50+ 家机构的中英文形式；抽不到时用**标题签名**去重，而不是退化成「来源线」（那会重建 8×3=24 格的退化）。实测 47% 条目成功归属机构 |
| 同一事实同时进 D 和 N，双重计分 | 来源分层**硬分区**：D/A 只数 Tier2+3；N 的因果深度只认 Tier1+2 |
| hurdle 的无风险收益是手工常数 | 取 Olive 美元货币基金货架**中位 7 日年化**（当前 3.3796%）；闲置现金也按此计息 |
| 评级门槛是绝对值，hurdle 一动全部漂移 | 并列一个**横截面四分位评级**，对 hurdle 标定免疫（已用单测证明缩放不变） |
| 只有价格止损，没有「论点失效」触发 | 新增 `thesis_invalidated`：主题预注册指标自建仓逆向 ≥1.5σ 且尚未触发止损 |
| 没有 as-of 纪律（7/23 的价格定 7/27 执行的区间） | briefing 里每个价格都来自已收盘交易日；成交只发生在批次生成时刻之后收盘的 bar |
| 因子缺失静默归一化 | 缺失项列在 `factors.TIS.missing` 里并打印 |
| `minimum_valid_reports: 5` 恒不满足 | 改为条目口径，门槛 12 条 |

### 2.3 刻意没改的

TIS 四因子权重（0.15/0.25/0.25/0.35）、情景赔率公式、S/A/B/C 绝对阈值、
主题分级门槛 75/60/45、三层强制层级（主题→传导→资产信号→表达工具）。

**保留是为了让 v0.4 的分数与历史 pack 可比。**

### 2.4 顺带发现：原 pack 的一处内部矛盾

导入 2026-07-27 历史 pack 时发现，赔率展开版底稿（10:16 HKT）
逐条标注「原页面核对 … 一致」，但它使用的概率/回报输入与它声称复现的 HTML
（SHA-256 `DC454DD…83085C`）中的 `updatedIdeas` **并不一致**。抽查 5 条，3 条不符：

| id | 工具 | 底稿情景回报 | HTML 情景回报 | 底稿 OR | 按 HTML 复算 |
|---|---|---|---|---|---|
| 21 | P/E FX | +10.0 / +2.0 / −6.0 | +8.0 / +2.5 / −5.0 | 2.29 | **2.64** |
| 29 | KRE | +10.0 / +3.0 / −7.0 | +8.0 / +2.5 / −6.0 | 2.44 | **2.26** |
| 4 | XLE | +7.0 / +1.5 / −9.0 | +8.0 / +1.0 / −8.0 | 0.79 | **1.43** |
| 9 | QUAL | +12.0 / +6.0 / −10.0 | 一致 | 2.20 | 2.20 ✓ |
| 7 | PAVE | +15.0 / +5.0 / −13.0 | 一致 | 1.96 | 1.96 ✓ |

底稿**自身的算术是自洽的**（用它自己的输入复算，5 条全部命中它自己印出的结果），

没有真正跑过**，只是被人工勾选了。

v0.4 把这条校验做成代码。跑 `ideagen verify-seed` 可复现上表。

### 3.1 为什么生成步骤是 Claude 而不是代码

这是你选的方案，也是对的：确定性规则引擎可复现，但写不出 thesis，
也做不了「这个主题虽然讨论热度高但已经很拥挤，所以降级为等待回踩」这类判断。

代价是不可复现，所以系统用三件事把它约束住：

1. **briefing pack 是唯一合法输入，且带 SHA。** 事后可以确认当时桌面上有什么证据。
2. **生成契约是硬约束**（`prompts/idea_generation.md`），15 条交付前自查。
3. **发布前校验是代码，不是勾选。** error 级失败即拒绝下单。

### 3.2 两个组合，为什么

| | 守纪律组合 | 无脑全买组合 |
|---|---|---|
| 仓位 | `pos_init% × 评级乘数`，单标的 ≤5%，单主题 ≤25% | 等权 |
| 进场 | 区间限价 / 突破触发 | 首个可成交收盘价 |
| 止损止盈 | 有 | 无 |
| 未成交资金 | 留现金，按货币基金收益计息 | 无 |

**两条线的差额 = 仓位管理的贡献。组合与 SPY 的差额 = 选股+择时的贡献。**
只有一条曲线的话，这两件事永远分不开。

### 3.3 让结果诚实的那几条规则

一个「每天下单看看」的系统很容易骗自己。这些是防线，每一条都对应一种常见的自我美化：

- **不可同 bar 回看。** 只能在批次生成时刻**之后收盘**的 bar 上成交。
  批次生成时间戳被存下来，`first_fillable` 据此推导第一个可成交交易日。
  （实测踩过一次：HKT 日期比美股交易日超前一天，差点漏掉一整个可成交 session。）
- **突破次日开盘成交。** t 日收盘确认的信号不能在同一个收盘价上执行。
- **限价成交取较差价。** 买入限价挂在区间上沿，成交价 `min(区间上沿, 开盘价)`——
  跳空穿过给跳空价，慢慢磨进去给区间边缘，**永远不给当日最低价**。
- **盘中不完整的 bar 直接丢弃。** OpenD 在盘中会返回一根正在形成的日线。
- **不可盯市的标的绝不进组合。** 而不是按成本价盯市——那等于凭空塞进一个 0% 收益。
- **闲置现金按真实收益计息。** 否则是在惩罚被检验的那个纪律本身。
- **敞口匹配基准。** 按设计只投 13% 的组合不该和满仓指数比。

开发过程中还抓到并修掉一个会显著虚高的 bug：
盯市循环没有 `opened_d <= d` 过滤，**重跑时会把后来才建的仓位盯到更早的日期上**，
第一天权益凭空多了 +5.7%。已加单测。

### 4.1 接入过程中的三个真实坑（都已在代码里注释）

1. **Wisburg 不声明 charset**，`requests` 会按 latin-1 解码成乱码；
   而且 SSE 载荷里有**裸换行**，按 `data:` 行切会截断 JSON。
2. **`startTime`/`endTime` 传裸 `YYYY-MM-DD` 会被上游误解析**，
   窄区间静默返回空页。必须传带 `+08:00` 偏移的完整 ISO-8601。
   （这个坑一开始让 market-daily / ec / articles 三条线全部返回 0 条。）
3. **必须按日分页。** 整窗口一次游标遍历会先截断最旧的一天，
   实测 feed 线 8/4 只拿到 105 条而 8/6 拿到 260 条——
   **A（三日升温）读到的就会是分页假象而不是真实升温。**

### 4.2 两个已知的数据限制

- **A股无行情权限**（`No permission... CN MarketETFs`），
  中国主题只能用离岸（MCHI/KWEB/FXI）与港股表达。
- **OpenD 历史 K 线有滚动 30 天不同标的额度**，本账户已用满 90 个；
  被挡的 5 个标的（XLF/XLI/XLP/XSD/XHB，都与已有标的重复）
  自动标记为不可盯市，生成器不会再选它们。

## 5. 实测结果（截至 2026-08-05 收盘，8 个交易日）

⚠️ **8 个交易日的样本没有统计意义。** 下面的数字是「系统跑通了、口径正确」的证据，
不是「这套方法有效/无效」的结论。真正的读数要等 30 天后、
以及 8/27（10 条 1 个月期到期）和 2027-01-27（30 条 6 个月期到期）。

### 5.1 组合层面

| | 守纪律组合 | 无脑全买组合 | SPY | 60/40 |
|---|---|---|---|---|
| 累计收益 | **+0.39%** | **+1.73%** | +4.18% | +2.65% |
| 权益 | $10,039,170 | $10,173,315 | | |
| 最大回撤 | −0.03% | −0.56% | | |
| 净敞口 | 13% | 100% | | |
| 成交率 | 24%（15/23 成交，8 条区间未触发） | 100%（23/23） | | |
| 超额 vs SPY | −3.78% | −2.44% | | |
| **超额 vs 敞口匹配基准** | **−0.19%**（12% SPY + 88% 现金） | **−2.44%** | | |

**读法：**

- 无脑组合 +1.73%，SPY +4.18%——**这批 idea 跑输了指数 2.44pp**。
- 守纪律组合只投了 13%，所以 +0.39% 的绝对数字没有意义；
  但**剔除仓位规模后只输 0.19pp**——说明「守纪律」本身没有亏钱，
  真正的差距来自「敢不敢上仓位」。
- 8 条 idea 的进场区间在 8 个交易日里从未被触及。方法论仓位（0.5%–3%）
  在这个市场环境下产生了一个几乎空仓的组合。

### 5.2 想法层面（等权，剔除仓位管理影响）

23 条可评分（另有 19 条无法盯市、40 条是今天新增持有期不足）：

| | |
|---|---|
| 等权收益 | **+1.70%** |
| 中位收益 | +0.42% |
| 胜率 | **65%** |
| 超额均值 | −2.45% |
| 跑赢基准比例 | **17%** |

**方向大多对（65% 上涨），但幅度普遍跑不过指数（只有 17% 跑赢 SPY）。**
在一个 8 天涨 4.2% 的市场里，选出来的东西涨得比市场慢。

### 5.3 排序能力

| 指标 | ρ vs 实际收益 |
|---|---|
| 中心期望回报 | **+0.573** |
| 中心赔率 | **+0.498** |
| 保守赔率 | +0.176 |

**这是目前最有价值的一个读数：中心期望回报的排序与实际收益的相关性达到 +0.57。**
n=23、8 天，远不足以下结论，但方向是对的——引擎认为好的确实表现更好。

有意思的是**保守赔率的排序能力（+0.18）明显弱于中心赔率（+0.50）**，
而 v0.3 的评级规则是用保守赔率定 S/A/B/C 的。
如果 30 天后这个差距还在，评级规则应该改用中心赔率。

### 5.4 概率校准

| | 中心 | 保守 | 均匀基线 |
|---|---|---|---|
| Brier | 0.523 | 0.491 | 0.667 |
| **技能分** | **+0.216** | **+0.264** | 0 |

技能分 > 0 表示优于「三分之一各一」的无信息先验。
但情景实现分布是 **base 91% / down 9% / up 0%**——
8 天太短，几乎所有结果都落在基准情景里，所以这个校准读数主要反映
「基准情景概率给得合理」，还没有真正检验上下行。

## 6. 反思

### 6.1 做对了的

**把「不可检验」当成头号缺陷来修。** v0.3 的公式其实都挺讲究，
但它缺的是一条从「打分」到「结果」的回路。加上 outcome 表之后，
排序 ρ +0.57、保守赔率排序能力明显弱于中心赔率、
「情景写夸张的确实更差」——这些都是原来永远看不到的东西。

**两个组合并行。** 只有一条曲线的话，「守纪律组合只赚 0.39%」会被读成
「这批 idea 不行」，而真实情况是「敞口只有 13%，剔除规模后只输 0.19pp」。

**把坑写进代码注释和 README。** Wisburg 的三个坑（charset、裸换行、
裸日期时间过滤）、OpenD 的额度和盘中 bar、macOS 的 TCC——
这些都是会重复踩的，写在代码旁边比写在文档里管用。

### 6.2 做得不够 / 明确的弱点

**① B 因子仍然是词典法，不是语义理解。**
立场编码靠正负词表匹配，反讽、条件句、双重否定都会误判。
当前 47% 的条目能归属到具名机构，另外 53% 靠标题签名去重——够用但不够好。
下一版应该把立场编码交给生成器逐条给理由，机器值作为先验对照。

**② N 的「意外程度」代理与 M 有结构性相关。**
两者都读同一个预注册价格指标。用价格波动当「有新意外」的代理，
可能只是在重复衡量「市场已经反应」。
需要在 30 天样本上测两者的相关系数，若过高应该从 N 中剔除、只留在 M。

**③ A 的强度项需要 20 天基线。** 现在只有 2 个打分日，强度项还是 NA，
A 退化成 v0.3 的重心项。**要到 9 月初这个因子才完全生效。**

**④ 基金类 idea 的日频曲线无法回溯。**
Olive 只给最新 NAV。历史 pack 里 17/40 条是基金，全部无法盯市，
只能记录并披露。**这意味着起点批次实际只检验了 23/40 条。**
从今天起每天快照，新批次的基金会有真实日频序列，但过去的补不回来。

**⑤ 生成步骤不可复现。** briefing pack 带 SHA、契约是硬约束、
校验是代码——但同样的 pack 喂两次，Claude 给出的 40 条不会完全一样。
这是选「每天 Claude 弄」必须接受的代价。

**⑥ 情景波动带 `[0.35σ, 2.60σ]`、拥挤度分段、四因子权重都还是先验值。**
它们本身就是待校准参数，现在只是「看起来合理」。

**⑦ 守纪律组合的仓位可能系统性过小。**
方法论仓位 0.5%–3%，40 条里大部分还是等待回踩，
结果是一个 13% 敞口的组合。这在原来的语境下是对的（PM 的真实账户有其他持仓），
但作为「检验 idea 质量」的载体，它的信噪比很低。
**可以考虑加第三个组合：只买 Q1 分位的 10 条，等权满仓。**

### 6.3 一个方法论层面的观察

原 pack 押注最重的能源主题（6 条）是唯一亏钱的一档（−1.30%，胜率 33%）。
而当日新批次里，能源供给依然是 TIS 最高的主题（73.3）。

这两件事不矛盾——7/27 那批能源 idea 亏钱是因为**当时 XLE 已经被新闻推高**
（原 pack 自己也写了「新闻冲击已经令 XLE 快速上行，必须等价格回踩」），
而今天 M=1.4 说明这一轮完全没被定价。

但它提出一个真问题：**TIS 高不等于赚钱。**
v0.4 加的 M 和 C 两个维度就是为了处理这件事，
30 天后应该能看到「高 TIS + 低 M + 低 C」这个组合是不是真的比单纯高 TIS 更好。
这是这套系统能给出的、v0.3 无法给出的答案。
