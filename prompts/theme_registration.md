# 主题注册契约 v0.4.1

每天生成 40 条想法之前,先处理一件事:**今天的语料里有没有字典还没有词的宏观辩论。**

## 为什么有这一步

主题字典最初是 16 条,写在代码里冻结。这么做的理由是对的——关键问题和价格指标必须在读价格之前登记,否则 M 因子会自己验证自己。但它顺带假设了**主题的集合是可以提前想全的**,而这个假设经不起数据检验:

- 5,836 条语料里,**2,688 条(46%)匹配不到任何一个主题**。
- 落在盲区里的不是边角料,而是当时活跃、来源充分的真辩论:GLP-1 与医保准入、韩国科技股重估、人形机器人、光模块出口管制、央行购金。

所以字典改成两半:代码里的 16 条种子 + 一个只能追加的注册表 `themes/registry.jsonl`。

## 唯一真正重要的规则

**注册日不可回填。** `registered_d` 必须等于今天,而 `lexicon.all_themes(as_of)` 只返回 `registered_d <= as_of` 的主题。

这条规则是整个机制能被信任的全部原因。没有它,「主题发现」就是**事后挑一个已经涨完的东西定义成主题,然后为自己排序准确而自豪**——这是所有回看错误里最难被发现、也最能自我欺骗的一种。有了它,今天注册的主题只能从今天开始打分,永远无法被记上一笔它没有做过的判断。

`themes.validate()` 会硬拒绝任何回填。别试图绕过它。

## 每天怎么做

### 1. 看候选

```bash
ideagen theme-candidates
```

或者直接读 briefing pack 里的 `theme_discovery` 字段(内容相同)。

输出的每个候选都带:命中篇数、独立机构数、跨天数、lift(相对窗口前基线的词频倍数)、来源层级、以及最多 14 条证据(doc_id + 标题 + 机构 + 层级 + 日期)。

准入门槛(全部要满足):≥8 篇 · ≥4 家机构 · ≥3 天 · lift ≥2.0 · 聚类后 ≥10 篇。

### 2. 判断哪些是真主题

**候选不等于主题。** 这一步是机械挖掘,它做的是「这些文档在讲一个字典没有词的东西」,它做不了语义判断。已知会漏进来的三类噪声:

| 噪声类型 | 例子 | 为什么不该注册 |
|---|---|---|
| **单个公司** | 小米集团、亚马逊、苹果、asm | 一家公司不是宏观主题。如果它真的重要,它属于某个已有主题的表达工具 |
| **研报系列名** | skynomad、某某周报 | 是栏目名,不是辩论 |
| **泛词碎片** | 下一、封装(需看上下文) | 语义太薄,注册后会匹配到大量无关文档 |

判断标准就一条:**这个词命名的是一个「未来 1–6 个月会有答案、且有可交易工具能表达」的分歧吗?**

- ✅ 因子轮动与拥挤交易解除 —— 有分歧(会不会延续)、有工具(VLUE/MTUM/RSP)
- ✅ 商业航天产业化 —— 有分歧(订单与首批财报能否支撑估值)、有工具(XAR/PPA)
- ❌ 小米集团 —— 是标的不是辩论
- ❌ 智能手机 —— 太宽,且已被 EARNINGS-QUALITY / CHINA-POLICY 部分覆盖

宁可少注册。一个注册错的主题会一直占配额、一直产出想法,直到 20 天不活跃被判休眠。

### 3. 写注册文件

```json
[
  {
    "id": "FACTOR-ROTATION",
    "label": "因子轮动与拥挤交易解除",
    "key_question": "未来1–6个月，从动量与AI拥挤交易向价值与防御的轮动能否延续",
    "terms": ["轮动", "rotation", "拥挤交易", "crowded trade", "unwind", "去杠杆",
              "价值股跑赢", "动量回撤", "momentum crash", "风格切换",
              "factor rotation", "价值成长", "value vs growth", "均权", "广度扩大"],
    "price_indicator": "US.VLUE",
    "related": ["US.MTUM", "US.RSP", "US.SPLV"],
    "default_direction": "↑",
    "exposures": ["美国价值股", "美国低波动股", "美国等权重大盘", "全球价值因子"],
    "provenance": ["以2026-08-06五日窗口 11篇/10家机构/3天 lift2.30 的零匹配语料簇为依据"]
  }
]
```

```bash
ideagen theme-register new_themes.json
ideagen score --force        # 新主题从今天起参与打分
```

### 字段要求

| 字段 | 要求 | 校验会拒绝什么 |
|---|---|---|
| `id` | 大写、连字符分隔,全局唯一 | 重复 id(注册表只能追加,不能改) |
| `label` | 中文短语,读得懂 | 空 |
| `key_question` | **必须含时间范围**(1–6 个月 / 个月 / month) | 无期限的问题——赔率是按 1–6 个月算的,答不了的问题打不了分 |
| `terms` | **至少 4 个同义表述**,中英混排 | 少于 4 个(只匹配一种写法的主题等于只匹配它出生的那一篇);与已注册主题重复的词(会在 D 里把同一份证据算两次) |
| `price_indicator` | 主 M 指标,**必须可定价** | 不在 instruments 或 priceable=0——不可盯市的指标会让这个主题产出无法计价的想法,以 0% 收益混进组合 |
| `related` | 最多 3 个佐证工具,同样必须可定价 | 同上 |
| `exposures` | 该主题可以通过哪些敞口表达 | — |
| `provenance` | 触发注册的证据摘要 | — |

**选价格指标时的诚实要求:** 从候选自己的证据里选,别从「哪个已经涨了」里选。校验拦不住这种动机,但 `registered_d` 让这么做毫无收益——今天注册的主题拿不到过去的任何功劳。

## 冷启动是已知代价,不是 bug

新主题没有自己的 20 天历史,所以 A 因子的强度项(当日热度在自身分布的百分位)算不出来,当天记 `cold_start=true`。这个标记会进归因分档,**所以「发现的主题是不是系统性更差」是一个可以被测量的问题**,而不是一个看不见的问题。30 天后要专门看这一档。

## 休眠

连续 20 个已打分日没有任何证据的主题标为 `dormant`,不再分配配额。**不删除**——过去的想法和 outcome 引用它,而且一个沉寂一个月的主题回来时,往往是账本里最值得看的东西。

## 每天都要看的一个数

`coverage_pct` = 当天语料里至少命中一个主题的比例。当前约 **54%**。

这个数字**下降**意味着发现机制跟不上语料了。固定 16 条主题的字典按构造就报不出这个数——它把自己的盲区变成了看不见的东西,这正是要修的问题。
