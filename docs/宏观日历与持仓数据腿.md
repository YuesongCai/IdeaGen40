# 宏观日历、隐含波动率、持仓：第五条到第九条数据腿

2026-09-05。起因是一个问题：「宏观日历那些是不是没有加进来啊？」

## 一、查出来的事实

日历这条腿**注册了，但装进去的不是日历**。

`ideagen/feeds.py` 里 `calendar` 是三个 kind 之一，链路从注册表一路通到
`events` 表和两个生成臂。管道没问题，问题在货：

| kind | 改动前条数 |
|---|---|
| `auction`（美债拍卖） | 51 |
| `level`（FRED 五个水平） | 13 |
| **`macro_release`** | **0** |
| **`policy`** | **0** |
| **`earnings`** | **0** |

`schema.py` 的注释写明这张表装四类事件，实际只落地了两类。**CPI、PCE、非农、
FOMC 一条没有。**

三个连带的窟窿：

1. 全表唯一的 `expectation` 是 `calendar_fred.py` 里硬编码的字符串
   「拍卖需求正常」，51 条一模一样。不是一致预期，是占位符。
2. `watchpoints` 表建好了、加了索引、`feeds.py` 专门写注释解释它为什么重要——
   **全仓 grep 不到任何写入点**，0 行。偏离触发只有 schema，没有实现。
3. 六个生成臂里只有两个看得见日历。而 `gen_carl` 的提示词硬性要求
  「给一个带日期或带水平的触发条件，『如果情绪转弱』不算」——它能拿到的日期，
   **只有国债拍卖**。

这不是新需求。`prompts/founding_principles.md` 的 Process 第 1 条写着
「数据源：wisburg 日报（周一–周三前三天）+ **宏观日历**」。缺的是初心里
明确点名、但一直只做了一半的那半边。

## 二、接进来的东西

五个新 feed（全部落在既有的 `calendar` kind，下游零改形），加一个默认关闭的语料 feed。

| feed | 内容 | kind | 实测 |
|---|---|---|---|
| `fmp_macro_releases` | 美国宏观发布日程，含一致预期 | `macro_release` / `policy` | 26 条／28 天 |
| `fmp_vol_surface` | 11 个隐含波动率指数 + 2 条期限结构比值 | `level` | 13 条 |
| `fmp_curve` | 美债曲线（FRED 没有的档）+ 2s10s / 3m10y | `level` | 6 条 |
| `fmp_cot` | CFTC 投机净头寸，13 个合约 | `level` | 10 条 |
| `fmp_congress_flow` | 国会披露交易，按板块汇总 | `level` | 9 条 |
| `fmp_news` | 市场新闻语料 | `corpus` | **默认关闭**，见第五节 |

日历腿从 11 行变成 64 行，其中头一次有了 26 条真实的宏观发布和 20 条持仓读数。

## 三、四个必须写下来的判断

### 1. IV 只能是指数层，因为 FMP 根本没有期权

`options-chain`、`option-chain`、`historical-options`、`implied-volatility`、
`volatility` **五条路径全部 404**。所以隐含波动率不是从期权链算出来的，是交易所
发布的指数。

这个限制正好指对方向。这本账持有的是基金和 ETF、对的是月度级别的宏观论点，
真正有用的是「市场愿不愿意为保护付钱、在哪一段期限上付」，不是某一只票的微笑曲线。
拿到的 11 个指数覆盖了股票期限结构（9 天到 6 个月）、波动率的波动率、纳指、罗素、
原油、黄金，以及通过 ^MOVE 和 ^VXTLT 覆盖利率——**这本账交易得最多的那个资产类**。

^SKEW 和 ^VXEEM 在这把 key 上返回空，没有当作常驻空值带进来。

### 2. 一致预期的覆盖率不随临近上升——我先猜错了

直觉是「越接近发布日，consensus 越全」。实测 60 天窗口，estimate 覆盖率按距离分桶：

| 距今 | 覆盖率 |
|---|---|
| 0–7 天 | 52% |
| 8–14 天 | 16% |
| 15–30 天 | 31% |
| 31–60 天 | 30% |

不是衰减曲线，是噪音。**真实规律是按指标定的。** 五个月窗口内 US High+Medium：

- **每次都有预期的 14 种**：CPI、Core CPI（MoM/YoY）、Inflation Rate（MoM/YoY）、
  非农、失业率、平均时薪（MoM/YoY）、劳动参与率、PPI MoM、续请失业金、
  初请四周均值、CPI s.a
- **从来没有的 7 种**：美联储官员讲话、CFTC 持仓公布、MBA 房贷利率——
  这些本来就没有 consensus 可发布
- 中间 46 种时有时无，都是二线指标

**最值得写触发条件的那几个，恰好是预期最可靠的那几个。** 平均数会低估这条腿的可用性。

### 3. COT 的 `symbol=` 形式冻结在 2024-02-27，且不报错

`commitment-of-traders-report?symbol=ES` 返回 HTTP 200、九行格式完全正确、
最新日期是 **2024-02-27**。GC、CL、NQ 返回同一个冻结窗口。同一端点族的
`from`/`to` 形式返回 301 行，最新到 2026-09-01。

响应里没有任何东西说它是旧的——没有错误、没有标记、schema 正确。照 symbol 形式读
出来的持仓不是「有点旧」，是**另一个时代**。所以 `fmp.cot()` 只发区间形式，
feed 还会拿 `as_of` 复核新鲜度，超过 21 天直接抛错而不是发出数字。

`fmp.cot_symbol_form_is_frozen()` 把这个证据留成可跑的探针而不是注释——
厂商哪天修好了，这条规则就该拿证据重新讨论，而不是靠一句 docstring 永远锁死。

### 4. 国会交易是个股而且极不均匀，所以必须汇总到板块

2026-09-05 拉的两院最近 200 条披露里，**68 条是一个议员在交易同一只微盘股**
（TKNO，占 34%）。这本账的 universe 是基金和 ETF，逐条个股既买不了，
还会把日历挤爆；按条数排名则会得出「国会最大的共识是一只没人能买的票」。

所以 feed 汇总到**板块**——universe 真正交易的那个高度——并且**把自己的集中度
和数字印在同一行**。用一个人一笔仓位算出来的板块净额，和三十个议员算出来的
是两个东西，读的人分不出来就会把噪音当共识。

日期一律用 `disclosureDate`，不用 `transactionDate`。STOCK Act 给 45 天，
实际合规参差，实测滞后到十个月。按成交日归期会把本期信号倒填到去年，
回放旧期次时还会看见当时并不公开的信息。

金额一律是**披露区间的中点**（披露只给区间，从不给数），每一处标签都写了
「非精确值」——一个看起来精确的美元数会被当成精确的引用出去。

## 四、落库：`events` 加了 `payload` 列

`feeds.py` 承诺「额外字段是允许并保留的——一个 feed 有有用的东西要加，
不该先来申请」。这个承诺**只在内存里成立**：`orchestrator` 的 upsert 写死十列，
其余全丢。于是 `impact`、`previous`、COT 的净头寸和反转趋势、国会汇总的集中度，
在进表那一步全部消失，回放读到的行比这次运行拿到的**薄**——运行和它的记录
不再是同一个东西，而 `backtest.py` 重读旧期次 `events` 时依赖的正是这条性质。

改法：`ADD_COLUMNS` 加一条 `("events", "payload", "TEXT")`，非核心字段
序列化进去。新库直接带、老库开机自愈（`schema.migrate` 每次启动都跑 `evolve`），
已有行不受影响。SQLite 和 MySQL 两套 DDL 都改了。

顺带修掉一个只在云上才会犯的错：`events.event_id` 在 MySQL 是
`VARCHAR(128)`，在 SQLite 是 `TEXT`。宏观发布的 id 里带事件全名，长的会被
MySQL 静默截断——`Core Inflation Rate MoM` 和 `Core Inflation Rate YoY`
截断后是同一个键，**在云端合并成一行，在本机怎么测都是对的**。
现在超长时截到 117 字符再接 10 位摘要，可读性保住、唯一性靠摘要。

## 五、`fmp_news` 为什么默认关闭

用户说的是「不止是 wisburg 作为数据源呀」，这个 feed 就是那句话。它也是今天唯一
一个写完不开的东西，理由写在这里而不是埋在代码里——「造好了但没开」只有在
开的条件被写下来时才算诚实。

1. **它改的是模型读什么，不是记录里有什么。** 今天其它 feed 都进 `events`，
   作为上下文抵达生成臂。这一个进 `corpus`，而 `corpus` 是筛选A 的输入——
   那个打分本身的准则是「热度为主 MECE」。在 40 篇研报里做词频加权，和在
   40 篇研报 + 一条新闻流里做，行为不一样，不是因为新闻更差，是因为**它更多**。
   模型输入中途切换会让后面的期次和前面的期次不可比——这条规矩是用户自己在
   穿透腿上定的。
2. **它还不是回放干净的。** `wisburg_corpus` 读的是 ingest 已经存下的行，
   回放旧的一周看到的就是那一周。这个 feed 现场调厂商，回放 2026-08-05
   会拿到九月的新闻挂在八月的 `as_of` 上。要开，得先在 ingest 时落库。
3. **初心里有一句指向反面的话**：「信息源 credible/stable 够了不用多」。
   这不是否决——同一份文件点名要「宏观日历」，所以今天其它东西照做——
   但它是一条应该由人刻意推翻的偏好，不该因为 feed 恰好写好了就自己翻。

开关：`IDEAGEN_CORPUS_FMP_NEWS=1`。开之前请先读上面三段。

## 五点五、把提示词渲染出来才看见的两个 bug

feed 全绿、测试全过、数据落库正确——然后把 `gen_carl` 和 `gen_gap` 的提示词
真正打印出来，两个缺陷立刻现形。**两个都不是 feed 的错，是读它的那两条臂的错，
而且任何只测 feed 的测试都测不出来。**

### 1. `gen_carl` 把已经发生的发布当成「可作为触发日期」

`fmp_macro_releases` 带了 7 天回看窗口（为了给 `actual`，将来结算 watchpoint 用）。
`calendar_block` 把所有非 level 行放进一个列表、升序排、截前 20——于是标题写着
「已排定事件（可作为触发日期）」，下面前十二行全是**已经公布过的**：
上周五的非农、上周三的 ISM。模型被要求给一个带日期的触发条件，
完全可能对着上周五写一条。

回看窗口本身是对的，甚至是这一页上对 Carl 式论点最有用的东西——
**已经发生的意外是现成的错位，比排定的事件更可交易**。它只是必须被标成它本来的样子。
现在分三段：未来事件当触发日期，最近已公布当证据（同时印预期和实际），水平当阈值。

### 2. `gen_gap` 的价格被新水平挤光了

`price_block` 原来是：先把日历里所有 level 拼进 `lines`，再 append 标的价格，
最后 `lines[:limit]`，limit=20。日历只有 5 个水平时这没问题。
今天变成 42 个之后，**20 行全被水平占满，标的价格一行都进不去**——
而这条臂的整个方法就是「从价格而不是叙事出发」。

共享上限一直是个潜伏的 bug，只是数据变多才让它发作。改成价格和水平各自有预算、
分两段渲染。

顺带加了一个 `priority` 字段：feed 可以声明自己这行有多中心。国会板块汇总是真的，
但和 VIX、曲线放在一起时是外围的——不排序的话，几个议员算出来的板块净额
会把全市场级别的读数挤出提示词。缺省值是「中心」，所以 `calendar_fred` 这些
早于这个字段的 feed 行为不变。

**记下来的形状**：feed 的正确性和它被读进提示词的正确性是两件事。
下次加数据腿，验完 `fetch()` 还要把 `build_prompt` 用到的那几个 block 打印出来看。

## 六、现在没做、明确留给下一轮的

- **`watchpoints` 还是 0 行。** `events` 第一次有了真实 `expectation`，
  这张空表才第一次有意义，但把「预期 → 偏离 → 动作 → 结算」写出来是新逻辑，
  不是加 feed。`fmp_macro_releases` 的回看窗口（默认 7 天）已经在带 `actual` 回来，
  就是为了让结算那一步有东西可比。
- **另外四个生成臂仍然看不见日历**。`gen_pm` / `gen_chain` / `gen_ai_native` /
  `gen_lookthrough` 不读 `ctx.calendar`。让它们读 = 改模型输入，同第五节第 1 条。
- **国会板块汇总要不要接穿透腿**。国会买的是个股，穿透层能算出哪只 ETF
  真正持有那批名字（军工那次实测 ITA 53.8% / XAR 26.1%）。两条腿接起来
  就是「国会在买的东西，用我们买得到的产品怎么表达」。
- **`fmp_congress_flow` 每次运行发 24 次 `profile` 调用**（板块解析），
  串行约 30 秒。周频可接受，但 `feeds doctor` 会明显变慢。

## 七、验证

`tests/test_macro_feeds.py`，25 条，全部离线（vendor 用替身），不依赖 key。
测的都不是崩溃，是**会被相信的、格式正确的错数字**：

- 2024 年的持仓被当作本周
- 一个人一只微盘股被报成「国会买入科技」
- `previous` 被提拔成 consensus，于是 watchpoint 对着环比波动报「超预期」
- 两个长事件名在 MySQL 截断后撞成一行，而本机全绿
- 空的波动率复合体被读成「今天市场没有隐含波动率」

厂商对上面每一种都回 HTTP 200，所以这些测试替的是传输层永远不会抛的那个错。
