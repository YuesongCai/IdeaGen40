# 主题形成：从当期研报出发，而不是从种子主题往上贴

> 对应 `docs/2026-09-06-jons-feedback.md` 第 1 条。落地日 2026-09-07，分支 `jon/themes`。
> 本文记录改了什么、规则常量是什么、在两期真实语料上跑出来什么、还有哪些没验证。

## 一、Jon 指出的缺陷，用代码的话说

旧流程（`themes.candidates`，2026-08-08 起）的挖掘对象是 `themes.unmatched()`：窗口内**没命中任何已注册主题**的研报。
一篇研报只要标题或摘要里出现一次「联储」，就被 POLICY-PATH 认领，从此它里面在争的别的东西——杰克逊霍尔上的鹰派转向、联储主席人选——永远进不了发现流程。
注册表实际起到的作用不是「对齐名称、追踪延续」，而是「决定本期允许发现什么」。这正是反馈原文的那句话：历史标签不应限定本期能发现什么。

第二个缺陷是命名时**看不见邻居**。`_mint_prompt` 只把当周已命名的卡放进提示，已注册主题一个都没有；模型没法说「这和 POLICY-PATH 是同一个争论」，只能要么写一张新卡、要么 skip。同一投资逻辑换个叫法被算成两个主题的口子就在这里。

第三个缺陷是没有冻结。任何一期打分用的主题定义集（哪些主题、各自哪些词）没有留下可对账的版本；注册表和词表改了之后，回头看一期的分数说不清它当时到底用了哪版定义。

## 二、改了什么

### 1. 发现范围：全窗口研报（`themes.candidates(scope=SCOPE_ALL)`）

- `window_items()` 给窗口内**每一篇**研报打上它命中的注册主题 `matched: [theme_id]`（判定与打分同一套：`lexicon.match_theme ≥ 1`）。
- `candidates()` 默认从全部研报挖短语簇；仍然排除已注册主题拥有的词项（`_known_terms(as_of)`，含别名），所以旧主题不会以自己的名字重新冒出来。
- `scope=SCOPE_UNMATCHED` 保留旧口径，用于并排对照；`coverage_pct / corpus_matched / unmatched` 在两种口径下数值相同（都是对全窗口算的），新增 `mined` 说明本次挖了多少篇。
- 每个候选簇多了 `relation` 与 `doc_ids`；`evidence` 每条多了 `matched`。

### 2. relation 规则（常量在 `themes.py` 顶部）

簇的证据里有多少篇同时命中了哪个注册主题，取重叠最多的那个主题算份额 `share`：

| share | kind | 含义 |
|---|---|---|
| ≥ `SPLIT_SHARE` = 0.6 | `possible_split` of X | 簇大部分长在 X 已认领的研报里：要么 X 换了叫法（别名），要么 X 内部长出了子争论（拆分）。哪一种由模型判。 |
| [`ADJACENT_SHARE` = 0.2, 0.6) | `adjacent` of X | 与 X 共享一片有意义的证据，但簇大部分站得住自己——邻居。 |
| < 0.2 | `distinct` | 那点重叠是任何两个宏观争论都会有的。 |

输出形如 `{"overlap": {theme_id: n_docs}, "kind", "of", "share", "n_docs_matched", "n_docs_unmatched"}`。
它是**提示，不是判决**：共享一篇研报不等于同一个争论，一篇研报可以同时讲两件事（反馈原文「局限」一节）。

### 3. 命名时带上邻近主题（`neighbours()`、`MINT_SYSTEM`）

提示里给出重叠最多的 3 个注册主题：id、中文标题、关键问题、前 6 个词项、共享篇数，以及机械判定。
模型必须先答关系，再决定写不写卡，判断标准写进了系统提示：驱动是否相同、验证条件是否相同、是否依赖同一事件/现金流/风险。三种回法、三条通道：

| 模型答 | 结果 |
|---|---|
| `same_debate` + `of` + `new_terms` + `rationale` | 不注册。`MintMerged` → `add_alias()` 追加到 `themes/aliases.jsonl`；journal 记 `theme_merge_note` |
| `split` + `of` + `rationale` | 注册，注册行带 `relation="split"`、`split_from`、`rationale`、`evidence_doc_ids`（前 20 条） |
| `distinct` + `rationale` | 注册，`relation="distinct"` |
| `skip` | 语料噪音，不是宏观争论。记在 `skipped`，不算失败 |

有邻居而不说 relation、或 `of` 指向本期看不见的主题，会被退回重写一次（沿用原有的「引用拒因重试一次」机制）。`validate` 拒绝 `relation="same_debate"` 的注册行（归并永远不能变成第二行），拆分的父主题必须在 `as_of` 已注册。

### 4. 归并 = 别名，不是新主题（`themes/aliases.jsonl`、`lexicon.load_aliases`）

- 每行 `{theme_id, terms, as_of, rationale, evidence_doc_ids, candidate_terms}`，append-only。
- `lexicon.all_themes(as_of)` 把 `alias.as_of ≤ as_of` 的别名并入该主题的 `terms`（另存 `alias_terms`、`aliases_through`）。回放更早的期看不到晚加的别名——与 `registered_d` 同一条钳制，堵的是同一个回看偏差的侧门。
- `add_alias` 的拒绝与 `validate` 对称：主题必须在 `as_of` 已注册；词不能已属于其它主题（同一条 stolen 规则，否则同一篇研报在 D 里计两次）；全是该主题已有的词算错误而不是空操作。
- 别名行的 `as_of` 早于主题 `registered_d`、或指向不存在的主题，**加载时**就报错（文件可手改，所以守在读的一侧）。

### 5. 冻结当期定义集（`themes.snapshot`、`A_theme_set.json`）

- `snapshot(as_of)` → `{as_of, theme_set_sha, n_themes, themes:[{id, label, registered_d, origin, terms_sha, n_terms, n_alias_terms, aliases_through, relation, split_from, …}]}`。sha 盖住决定匹配与打分的一切：id、注册日、关键问题、指标、方向、`require`、**并入别名后的词表**。
- 周跑在主题发现之后、筛选A 之前写 `A_theme_set.json`，journal 记 `theme_set` 步；`theme_set_sha` 写进 `topics` 步和每个 topic_scorer verdict 的 `meta`（含对照打分器）。
- `review.weekly_block`：`topics[*].theme_set_sha`、顶层 `theme_set_sha`；`themes[tid]` 多了 `relation / rationale / split_from / evidence_doc_ids / alias_terms / aliases`（面板由另一位接）。
- 性质：同一期、同一注册表与别名文件 → 同一 sha；落在期内或之前的注册/别名 → sha 变；落在期后的 → 不变（测试 `TestSnapshot` 盯着）。

### 6. 周跑循环搬进 `themes.discover()`

orchestrator 的主题发现块缩成一次调用；循环本身能用假模型端口单测。journal 步：`theme_register_failed`（逐条）、`theme_merge_note`（逐条，含 `alias_written` 与失败原因）、`theme_discovery`（一次，汇总 `registered / merged / skipped / failed`；没有模型时带 `error` 说一次）。

### 7. CLI

- `ideagen theme-candidates`：默认全窗口，`--unmatched-only` 回到旧口径；每个候选打印 `relation kind/of/share`、已命中/未命中篇数、overlap 前 4 个、证据行尾的 `[命中主题]`。
- `ideagen theme-register`：打印 relation / split_from / rationale。
- 新增 `ideagen theme-alias <THEME-ID> <词1,词2> --rationale ...`：人工归并入口。

### 案例回答 Jon 的三个问题

1. **同一争论的不同表述能否归并？** 能——「沃什」对 `Warsh`、「息预期升温」对「加息」，机械关系都指向 POLICY-PATH，提示里带着它的关键问题和词项，模型有材料判 same_debate；判了之后走别名，不产生第二行。
2. **行业相同但驱动不同的观点能否区分？** 「取消预售制度」对 CHINA-POLICY 是最清楚的一例：share 0.96 说明它完全长在 CHINA-POLICY 的研报里，但关键问题不是一回事。这是 `split` 通道存在的理由；判定本身仍是模型的，本文只证明材料到位。
3. **已经命中旧主题的研报中，新观点能否被发现？** 两期各一例（杰克逊霍尔 08-26 前瞻、09-02 鹰派首秀），旧口径两期都是 0 个候选。

## 四、局限与还没验证的事

- **共享研报 ≠ 重复。** relation 只是重叠计数；`of` 会被词表宽的主题吃掉——EARNINGS-QUALITY 的词（盈利/业绩/指引/margin）几乎每篇都命中，所以 08-26 的杰克逊霍尔簇被判成 EARNINGS-QUALITY 的邻居而不是 POLICY-PATH 的。提示给前 3 个邻居而不是 1 个，就是为了让模型看见 INFLATION 与 POLICY-PATH。根治要动词表宽度，不在本次范围。
- **归并过度 / 拆分过细都还没在真实模型上跑。** 本次没有调用模型（本机没有推理端口），模型通道只用假端口验了契约：same_debate → 别名、split → 带 split_from 的注册行、of 指错 → 退回重写。真实模型对「取消预售制度」是判 split 还是 same_debate，要等下一次周跑的 journal。
- **噪音碎片。** 全窗口口径把挖掘对象从 171 篇放大到 1109 篇，n-gram 碎片（「及关」「与高」「至超」）随之增多；14 个候选里我读下来只有 4 个值得进模型（杰克逊霍尔、预售、沃什、天气）。`MAX_CANDIDATES=8` 会截掉排在后面的；碎片如果排在前面会占名额。7 字以上的短语（杰克逊霍尔会议）被 6-gram 上限切成两个碎片，也在这里。
- **公司名。** 财报季公司名（美团/比亚迪/腾讯/名创优品）每期都会过四道门。系统提示第 2 条要模型 skip 它们，这一条同样没在真实模型上验过。
- **别名只做了精确冲突检查**（与 `validate` 同款），没做子串检查：「算力租赁」给 AI-CAPEX 没问题，但一个含「算力」的词给别的主题不会被拦。
- **快照没有回填。** 09-07 之前的期没有 `A_theme_set.json`，`weekly_block` 对它们报 `theme_set_sha: null`，不编造。
- **`_SkipDiscovery`** 在 orchestrator 里已无人引用，留着没删（同文件有其它并行改动）。
