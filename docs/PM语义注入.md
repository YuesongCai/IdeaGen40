# PM 语义注入：一句话怎么进到系统里

> 落地代码：`ideagen/philosophy.py`、`ideagen/strategies/gen_pm.py`、
> `prompts/founding_principles.md`、`tests/test_philosophy.py`
> 命令：`ideagen philosophy list | propose | activate | retire`

## 问题

PM 有一套自己想交易的方式——「我不买已经被讲烂的东西，我要的是被迫的卖家」——
系统里现在没有任何地方接得住它。四个生成臂的推理骨架是写死在代码里的。

最省事的做法是给 Carl 臂加一个输入框，把话拼进 prompt。**这个做法会同时毁掉四样东西：**

| 现在有的 | 加个输入框之后 |
|---|---|
| 四臂可比（plumbing 逐字节相同，只差推理骨架） | Carl 臂的历史序列变成好几个不同策略的混合，胜率不再有含义 |
| verdict 可复现（RunContext 冻结 + inputs_sha 哈希） | 覆盖层不在哈希里，几个月后重放静默地跑出别的东西 |
| 分数可归因（每行带 strategy + version） | prompt 变了版本没变，存下的分数指不回产生它的逻辑 |
| 抵抗过拟合 | 每周三对着上周盈亏拧一次 = 在 4 个样本上做人肉梯度下降，正是 Jon 08-18 提的 multiple testing |

## 做法：注入不是编辑，是一次出生

```
一句话  ──蒸馏(AgentKit/ModelArk)──▸  准则卡  ──▸  carl_constraint@pm-xx   ← 新臂
                                                    carl_constraint        ← 原臂冻结，当对照
```

原臂 prompt 逐字节不动，历史序列不断。派生臂从生效日起有自己的序列，诚实地从 n=1 开始，
和原臂**同一批候选、同一次取数、同一套解析**，只差那张卡。

四周后「PM 这句话值多少」是两条臂在配对周上的差，不是印象。
跑不赢它嫁接的那条臂的哲学，就是账本不该拿着的哲学——只有这种排布下这句话才成立。

## 注入点为什么在筛选B

| 阶段 | 注什么 | 结论 |
|---|---|---|
| 筛选A 主题 | 「我关心什么宏观」 | **不开放**。改题目等于改掉整周，下游每一处差异都有两个可能的原因 |
| **筛选B 出想法** | **「我怎么想一笔交易」** | **开放**。Carl 臂本身就是一副推理骨架（异常→动机→约束→触发），PM 的 philosophy 本质上也是。同构，所以接得上 |
| 筛选C 定持仓 | 「我怎么取舍」 | **不开放**。松紧、止损、排序键已经是声明过的参数臂，自由文本只会做出一个扫不了的重复品 |

代码上的位置：`gen_carl.build_prompt` 里骨架之后、输出契约之前。
这是唯一一个能让哲学参与推理、又够不着共享 plumbing 的位置。

## 三条约束在做实际的活

### 1. FROZEN：卡永远碰不到的东西

可买清单、引用契约、JSON 形状、一个月期限、每主题条数、只做多、赔率定义、
**仓位与止盈止损**（归筛选C 与建仓，生成臂说了不算）。

这些是共享 plumbing——四臂靠它们完全相同，收益差才只可能来自推理骨架。
卡碰到它们，就是同时改了尺子和被量的东西。

蒸馏时告诉模型，落库时再机械查一遍：**被告知边界和存在边界不是一回事。**

### 2. 每条准则必须落成一个必填字段

这是让哲学可检验而不是装饰的那一步。

- 「找被迫的卖家」写进 prompt → 得到**也许**找了的想法
- 同一句话带上 `require: forced_seller` → 得到指名了主体、条款、期限的想法，
  或者一条**带原因的丢弃记录**

一个月后「这条哲学到底有没有被执行」两边都有答案。丢弃率本身还回答了另一个问题：
语料撑不撑得起这种想法。

### 3. ledger 只增不改，按 as_of 生效

卡只能新增和停用，不能改写。运行只看见 `as_of` 早于自己的卡。
让九月写的哲学去跑八月，和用已印出的 K 线给事后想法成交是同一种作弊
（`first_fillable` 在成交那边拒绝的就是这个）。

## 改写必须由说话的人亲自过目

拿真话跑第一遍就发现了一个 fail-open，值得单独记：

PM 说「该做空的时候也要能做空、拿三个月、别被清单限制死」——三处全在硬边界外。
蒸馏器老实地把三处都记进了 `touches_frozen`，写成
`"direction: 原话要求做空，已改为买反向标的做多表达"` 这样的散文；
而体检做的是精确 key 匹配，一条都没对上，**全部放行**。

真正的风险不是模型越界（它没有），是它替 PM 把话改了却没人告诉他：
他说做空，系统给他反向 ETF；他说三个月，系统给他一个月。改得都对，
但那不再是他说的话，而他会在十一月复盘时才发现。

所以 `touches_frozen` 从「失败」改成「**改写**」：子串匹配捞出来，
`activate` 见到未确认的改写直接拒绝，必须 `--accept-translation` 才放行。

同一轮还抓到两个：

- 模型给过「排除被两家主流财经媒体上过头条的主题」——它手上只有那批研报，
  查不到头条。**这种准则不会让模型照做，只会让它编一个像样的理由。**
  蒸馏提示加了可执行性一条，重跑后它自己改成「在提供的研报中被反复提及」——
  同样的意思，但能从材料里读出来。
- 模型给过「确定性高的仓位设为 2 倍」——生成臂没有通往账本的通道，
  这条写了等于没写，而 PM 会以为它在跑。`sizing` 因此进了 FROZEN。

## 怎么用（面板，`http://localhost:8765/#/rules`）

左侧导航第三格「准则」。三步，全程不出现 card_id、臂名、筛选B、require 这些词——
用这个功能的人不需要知道系统是怎么造的。

**① 写一句话** → 点「生成草案」（约二十秒，走 ModelArk 蒸馏）

**② 核对草案**，屏上按人真的会问的顺序答三件事：

| 分段 | 回答的问题 |
|---|---|
| 系统据此执行的要求 | 我说的话，它听懂成了什么 |
| 今后每条想法都必须回答 | 多出来哪些必答字段（答不上的想法会被丢弃，不会凑数） |
| ⚠️ 你的准则有部分被改写 | 它替我改了哪里——**只有这一项必须勾选确认才能继续** |
| 生效后会发生什么 | 新增一条臂、原臂冻结做对照、四周后给对比 |

**③ 点「确认生效」**。下一次周跑（周三）这条臂第一次生成。

「在跑的准则」列出每条的原话、生效日、已跑期数、必答字段，以及「停用」。
停用后它已经写下的持仓与业绩留在账本中。

**降级与边界**：本机没开推理时，输入区替换成一行说明，查看不受影响；
公开快照页（GitHub Pages）里这一格**不注册**——静态导出没有后端可写，
注册了就是一格点进去没反应的死链。

### CLI（同一套东西，脚本化时用）

```bash
ideagen philosophy propose --arm carl_constraint --say "……"
ideagen philosophy activate <card-id> [--accept-translation]
ideagen philosophy list
ideagen philosophy retire <card-id> --reason "四周跑输原臂"
```

`propose` 刻意停在一个文件上。蒸馏是一次模型调用，模型是这条链上最不可信的一环；
一个句子被解析得很流畅就开始操盘，正是这套设计要避免的那个无人过目的旋钮。

## 账本放在哪

`data/philosophy/ledger.jsonl`，**gitignore**。它是 PM 自己的话 + 本机运行状态，
跟 `data/ask_log.jsonl` 同一性质。

但它是复现一次运行的一部分，所以由**审计包**带走（`08_当时生效的准则.json`，
按运行当天的 as_of 取）。少了它，换台机器重放会按四条臂重建一个当时有五条臂的
运行，而多出来那条臂的持仓在包里找不到任何解释。

同一轮顺手修了审计包的另一个洞：它按 `GEN_ZH` 这张**手写名单**收生成臂的产物。
四条臂已经不是全集了，按名单构包漏掉的恰好是有人特意加进去的那一条。
改成和选取臂一样的发现式——那段代码的注释早就写过这条理由。

## 还没做的

- **效果读数**。派生臂会跑、会记、会进审计包，但面板还没有「这条准则 vs 原臂」
  的配对差值视图。现在只显示「已跑 N 期」，N=0 时明说尚未运行。
- **另外三条臂**。`BASES` 加一行 + 那个生成器的 `build_prompt` 接同样的
  `card=None` 参数即可；边界是靠那个参数的插入位置守住的。
- **一次多条准则**。目前一张卡一条准则，故意的：多条一起注入，跑赢跑输归因不到
  哪一条。要多条就分开写、各自派生一条臂。
