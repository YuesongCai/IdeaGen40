# 前端用户旅程与信息层级

本文在改动任何 UI 之前定义：谁来、来做什么、完成后去哪、页面唯一主行动是什么、
哪些信息必须立即看到。线框与层级在这里定稿，视觉风格不在本文讨论范围。

适用范围：`web/dash.html` 的两个页面（`week` 组合 / `process` 链路），
数据契约为 `/api/state`（见「四、接口契约」）。

---

## 一、两类用户，两条旅程

面板今天把两类人的需求平铺在同一页，这是「不够直观」的根因：
他们要的第一句话不是同一句。

### 旅程 A — 运营者（每周 1 次 + 出事时）

| | |
|---|---|
| 从哪里来 | 周三早上想起「今天该跑了」；或收到异常通知 |
| 此刻最想完成的一件事 | **确认这一期是否正常产出；不正常时知道卡在哪一段** |
| 完成之后去哪 | 正常 → 关掉页面；不正常 → 进入卡住的那一段看原因 |
| 主行动 | 无需操作即可得到结论。异常时唯一主行动是 **「查看卡住的环节」** |
| 判断成功 | 十秒内能说出「跑完了 / 在跑 / 挂了，挂在第几段」 |

### 旅程 B — 评审者（不定期，含 Jon 的方法论评审）

| | |
|---|---|
| 从哪里来 | 想回答「这套方法有没有效、凭什么信」 |
| 此刻最想完成的一件事 | **判断当期结论的可信度，并能回溯到原始依据** |
| 完成之后去哪 | 下钻到某一段链路的凭据（研报原文、评分、落选理由） |
| 主行动 | **「打开本期链路」** |
| 判断成功 | 能独立复述「结论是什么、样本够不够、哪些不能下结论」 |

**结论：两条旅程对应两个页面，各自只留一个主行动。**
组合页服务旅程 A，链路页服务旅程 B。今天组合页同时承担了两者。

每页首屏必须在几秒内答完三问，答不出的内容一律下沉。

### 组合页（week）

|---|---|---|
| 这是什么 | ✗ 标题只有「组合」 | 本期（2026-09-02）的模拟组合与运行状态 |

### 目标分级

**第一档 · 必须立即看到**（首屏，不超过三件事）
- 本期状态一句话：跑完 / 在跑（第几段）/ 失败（卡在第几段）
- 本期组合损益一个数 + 同期基准对照一个数
- 当期结论的效力级别：**「第 1 周，尚不具备区分度」**——这句必须在首屏，
  否则读者会把噪声当成排名。

**第二档 · 可折叠**（默认收起，标题即结论）
- 主链路 01–03（收起时只显示三段的数量）
- 选取策略对比（收起时只显示「10 个账本，差异全部落在噪声区间内」）
- 历史回测（收起时只显示「6 期 · 无策略被判定跑赢全量基准」）

**第三档 · 可悬浮**（hover / ⓘ，不占版面）
- 术语：pp、噪声区间、预注册可检出差距、配对检验、时间钳制、as-of
- 各策略的一句话定义（赔率排序·严格 = 赔率排序·高阈值）
- 口径差异说明（本表以单条想法为单位 / 对比图以账本为单位）

**第四档 · 可下钻**（点进去才加载）
- 10 张策略卡片明细（今天与点阵图重复，应合并为点阵图的下钻）
- 主题分布条（同上，合并为下钻）
- 主题敞口 38 标的气泡图
- 完整回测、审计包

**删除或改写**
- 回测下方三段自我解释长文 → 移入 ⓘ 与下钻页，首屏只留一句结论
- 「各策略的主题分布」与「策略卡片表」不再与点阵图并列展示

## 四、状态设计（四态一律前置设计）

按 RockFlow 原则 9：默认系统会失败。以下每一态都要有明确形态，不是事后补。

| 状态 | 要求 | 现状 | 处置 |
|---|---|---|---|
| Loading | 阶段性反馈，不是白屏 | ✗ 曾白屏 8.3 秒 | 服务端已降到 0.46 秒（见下）；仍需骨架屏兜底 |
| Error | 说明失败在哪一步，可重试且不重复提交 | ✗ 无 | 按模块给出「这一块没取到，重试」 |
| Empty | **区分「确实没有数据」与「没取到数据」** | ✗ 混同 | 见 `ports_pending` 契约 |
| Partial | 单模块失败不拖垮整页 | ✗ 单文档全有全无 | 模块级降级 |
| 数据过期 | 有时间标识 | 部分有 | 每个异步结果带自己的时间戳 |

### 已落地（服务端，本次迭代）

`/api/state` 的端口自检原本每 60 秒对远端对象存储做一次 `list_objects`，
占 3.3 秒构建时间中的 2.9 秒。已改为 TTL 缓存 + 后台刷新 + 启动预热：

| | 改前 | 改后 |
|---|---|---|
| 响应时间 | 8.30 s | **0.46 s**（−94%） |
| 传输体积 | 806,357 B | **95,352 B**（−88%，紧凑 JSON + gzip） |

契约新增字段（`alive` 下，向后兼容，只增不改）：

| 字段 | 类型 | 含义 |
|---|---|---|
| `ports` | `[{name, ok, detail}]` | 端口自检结果，形状不变 |
| `ports_checked_at` | `string \| null` | 这份结果是什么时候测的（HKT ISO） |
| `ports_age_s` | `number \| null` | 距今多少秒 |
| `ports_stale` | `boolean` | 超过 TTL，仍可读但已过期 |
| `ports_pending` | `boolean` | **还没测到，不等于端口挂了** |

> 前端必须消费 `ports_pending`：`ports` 为空数组时若按「无异常端口」渲染，
> 就把「没取到」谎报成「一切正常」——这正是 Empty 态必须区分的两种情况。

## 五、组件分层

抽象克制：一个模式在 **2–3 个场景稳定复用之后**再抽，不为架构美感提前造万能组件。

| 层 | 内容 | 现状 |
|---|---|---|
| 基础层 | Button、Badge、Pill、Text、Icon、Tooltip(ⓘ) | 部分存在，散落 |
| 组合层 | 指标卡、策略行、阶段条（01/02/03）、可折叠区块 | 存在但未统一 |
| 业务层 | 主链路模块、策略对比面板、主题敞口模块、回测模块 | 存在 |
| 页面模板层 | 组合页、链路页 | 存在 |

### 现在就该统一的三件事

1. **可折叠区块**：第二档信息全部依赖它，是当前最该先有的组合层组件。
   收起时标题必须是结论，不是分类名。
2. **ⓘ 术语气泡**：第三档全部依赖它。术语表集中一处，页面引用而非各自写文案。
3. **策略这个概念**：点阵图、卡片表、主题分布条三处各自演化。
   必须收敛到同一套字段名（`name` / `label` / `kind` / `delta_pp` / `positions`）
   和同一个组件，业务差异走 props。

### 判断标准

> 改一处样式或一句文案时，是否只需要改一个地方。

今天「赔率排序 · 严格」这个名字在三个地方各写一次——不达标。

## 七、本次迭代的验收口径

1. 用户是否更容易完成目标 —— 十秒内能否说出本期状态。
2. 业务结果是否准确可信 —— 「没取到」不再显示为「正常」。
3. 失败时是否安全可恢复 —— 单模块失败不拖垮整页。
4. 下一次迭代是否更便宜 —— 改一处文案是否只改一个地方。

# 八、整体导航重构（2026-09-05）

## 问题：15 个目的地，2 格地图

盘点当前所有可达位置：

| 层 | 数量 | 现状 |
|---|---|---|
| 顶层视图 | 2 | 侧边栏：组合 / 链路 |
| 页内区块 | 6 | 组合页平铺，无锚点 |
| 抽屉 | **13** | 阶段 / 账本 / 可信度 / 运行记录 / 运行日志 / 主题 / 候选想法 / 持仓 / 语料 / 追问 / 追问记录 / 状态自检 / 堆叠阶段 |

**13 个抽屉没有一个是可寻址的**。`history.replaceState` 只处理两个顶层视图。
后果：产品的全部深度都藏在「点开才知道」的抽屉里——看不见、分享不了、回不去，
也无法从 URL 判断自己在哪。侧边栏只有两格，等于告诉用户「这里只有两个地方」。

这是「不够直观」的结构性原因，不是配色或间距问题。

## 从 Nexus 前端学到的三条

参考 `1-frontend/main/src/views/nexus-next`：

1. **侧边栏只放顶层领域，保持扁平**（首页 / Agent Hub / 产品库 / 客户 / 订单 / 交易 / 设置）。
   规格：展开 220px、收起 60px、`width 240ms cubic-bezier(.22,1,.36,1)`；
   激活与 hover 同用 `--color-surface-sunken`；收起后图标 + tooltip（portal 渲染）。
2. **子层级不塞进侧边栏，用页内 tab 承载，状态放进 URL**
   （`/clients/:id?tab=funds`）。
3. **导航契约用类型固定**，这是本次最该抄的一条：
   `ClientDetailTab` 联合类型 + `parseClientDetailTab()` 安全兜底 +
   `buildClientDetailPath()` 统一构造，且默认值不写进 URL。
   没有人手写 URL 字符串，每个子视图都可寻址、可分享、可回退。

## 目标结构：3 个领域 + 10 个子项

按两条旅程切，而不是按数据结构切：

```
组合  portfolio        「这周产出了什么」
  概览      /portfolio              损益 · 基准对照 · 当前敞口
  持仓      /portfolio/holdings     主题敞口分布 → 下钻单标的
  选取策略   /portfolio/strategies   10 个账本对比 → 下钻单账本

链路  chain            「凭什么信」
  01 读研报  /chain/corpus          语料来源与分布
  02 选主题  /chain/topics          HGEP 评分与落选理由
  03 写想法  /chain/ideas           方法与候选池
  回测与局限 /chain/trust           未验证假设 · 已修复缺陷 · 历史回测

运行  ops              「跑没跑成」
  本期状态   /ops/status            心跳 · 端口自检 · 数据源
  运行记录   /ops/runs              按期查看
  运行日志   /ops/log               逐步日志与审计包
```

三个领域正好对应：旅程 B 的结论（组合）、旅程 B 的依据（链路）、旅程 A（运行）。

## 路由契约

slug 一律用拉丁字母，**不拿显示文案当标识**——文案会改、会切语言，
标识不能跟着变。同一套 slug 同时作为埋点 `element_id` 的前缀。

| 规则 | 说明 |
|---|---|
| 形态 | `#/<domain>` 或 `#/<domain>/<section>` |
| 默认子项 | 不写进 URL：`#/portfolio` 等价于 `#/portfolio/overview` |
| 下钻 | 追加查询：`#/portfolio/strategies?book=odds_strict` |
| 解析 | 单一 `parseRoute()`，无效值回落到该领域默认子项，不抛错 |
| 构造 | 单一 `buildRoute()`，不允许手写 URL 字符串 |

## 分期实施

| 期 | 内容 | 状态 |
|---|---|---|
| 一 | 侧边栏子项；锚到现有区块；滚动高亮当前子项 | **已完成 2026-09-05** |
| 二 | `parseRoute` / `buildRoute` 契约；顶层视图与子项进 URL | **已完成 2026-09-05** |
| 三 | 13 个抽屉逐个接入路由，可寻址、可分享、可后退 | 待做 |
| 四 | 「运行」领域独立成第三个顶层（现为抽屉：状态自检 / 运行记录 / 运行日志） | 待做 |

一、二期实施记录：

- 子项只在对应区块**真的渲染出来**时才出现在地图上——一个点了没反应的
  目的地比没有这一格更糟。
- 顺带修掉两个真实缺陷：
  1. **正确性路径不该依赖 `requestAnimationFrame`**。深链跳转原本挂在 rAF 上，
     标签页隐藏时 rAF 一帧都不触发，跳转静默失效。已改为 `setTimeout`。
  2. **`behavior:'smooth'` 会被静默忽略**（无头浏览器、关动效环境），
     滚动根本不发生。已改为自绘缓动 + 定时器兜底落位，并尊重
     `prefers-reduced-motion`。
- 页面真正的滚动元素是 `<html>`；`body` 声明了 `overflow-y:auto` 却滚不动，
  `scrollIntoView` 会被它误导。锚点跳转一律换算成文档坐标后滚动窗口。

一期不动任何内容区块，只让地图显形——先让用户看得见这个产品有多深。
