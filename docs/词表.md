# 词表：面板上每个词到底指什么

> 2026-09-05。起因：用户看着面板说「**账本到底啥意思，通篇说到账本就听不懂，
> 他难道不是一个持有方法吗？**」——他是对的，而且他的说法比原来那个词准确。
> 这份词表记录这次改了哪些词、为什么改，以及哪些词**故意没改**。
>
> 判断标准只有一条：**这个词说的是「这东西是什么」，还是「它在系统里怎么存的」。**
> 后者是实现细节漏到界面上，一律改掉。

## 改掉的

| 原来叫 | 现在叫 | 它其实是什么 | 为什么原来的词不对 |
|---|---|---|---|
| **账本** | **组合** | 一个选取策略配一个纸面组合：$10m 等资本、等权买入、进场即挂 σ×2 止损 / σ×3 止盈、滚动持有一个月。十个组合吃同一份候选池，唯一差别是选取策略 | 「账本」讲的是它**存在哪儿**（一本账），不是它是什么。用户读到的是一个持有方法，那就该叫组合。config 里本来就写着「挑法组合」，只有面板叫账本——同一个东西两处两个名字 |
| **一本账 / 每本账 / N 本** | 一个组合 / 每个组合 / N 个 | 同上 | 量词跟着比喻走，比喻换了量词也得换 |
| **入账 / 已入账** | **建仓 / 已建仓** | 这一期选出来的想法真的下单成交了 | 「入账」是记账动作。读者要问的是「买没买」，不是「记没记」 |
| **各记一本账** | **各管一个组合** | 十个选取策略互不共用现金 | 同上 |
| **臂**（arm） | 按它所在的阶段叫真名 | 见下 | 多臂老虎机（multi-armed bandit）的黑话，直接漏到了界面上。而且它在面板里其实指**三种不同的东西**，同一个字读者根本分不开 |
| └ 筛选A 里的臂 | **打分方法**（语义打分 / 计数对照打分） | 两种给主题打分的做法并行跑，比谁选得准 | |
| └ 筛选B 里的臂 | **生成方式** | 四种出想法的做法；PM 写一条准则会派生出第五种 | |
| └ 筛选C / 统计检验里的臂 | **组合** | 就是上面那十个 | |
| **语料** | **研报** | Wisburg 研报 +（宏观日历另算） | NLP 黑话。输入就是研报，面板别处已经在写「研报语料 · Wisburg MCP」，自己跟自己重复 |
| **空语料** | **没有研报** | 这一期一篇都没抓到 = 运行失败，不是「本周没料」 | |
| **挑法** | **选取策略** | 筛选C 的十种选法 | 用户 2026-09-04 已拍板：术语化优于口语化。这次把 review.py 和 config.py 里漏网的几处补齐 |
| **准则账本** | **准则记录** | PM 写下的准则清单，只增不改 | 这个**确实**是台账，但它不是组合。账本一词退场之后，得给它一个不跟组合撞的名字 |

### 一句话说清关系

> **一个选取策略 = 一个组合。** 十个选取策略看**完全相同**的候选池，各挑一份、
> 各管一个组合、各自记价。净值之差只可能来自「挑得不一样」——这就是为什么会有
> 「全量基准」「随机基准」这种明显不聪明的组合：它们是对照组。

## 闸门：`tests/test_glossary.py`

换完词不到四个小时，「臂」就被写回了两处；当天下午又抓到三次。这个仓同时有
十几个 Claude 会话在写 `web/dash.html`，谁都可能没读过这份文档。**文档拦不住，
红的测试可以**——而且 `cloudsync` 推代码前跑全量测试，所以它同时挡住了旧词上云。

它查两类东西，判据不同：

| | 查什么 | 判据 |
|---|---|---|
| 中文旧词 | 账本 / 本账 / 入账 / 语料 / 臂 / 挑法 | 出现即违规 |
| 裸英文 | live / as_of | **紧挨着中文才算**——「结论以 live 期为准」拦，`class="pchip live"`、`alive`、`SELECT as_of FROM` 不拦 |

范围是 dash.html 去注释后**含中文的字符串字面量**，加上 `ideagen/` 与
`scripts/` 下所有模块里非 docstring 的字符串（f-string 整条还原，否则例外
清单永远匹配不上整句）。注释和 docstring 不管。

**默认全扫，不用手写清单。** 第一版列了 13 个文件，一量才发现另有 14 个模块、
68 处旧词漏在外面。手写清单挡不住新模块——豁免要写理由，而且豁免清单自己也有
测试（文件改名之后那条豁免会悄悄免掉一个不存在的东西）。现在只有两条豁免：
`retag_backtest_summary.py`（它本身就是旧词→新词的对照表）、
`generate_batch_2026-08-07.py`（一次性产出与当时的判断记录，改它等于改历史）。

**还有一条对账**：`SEL_META`（面板给选取策略取中文名的唯一对照表）必须覆盖
后端注册的每一条 `idea_selector`。它是一份手工维护的注册表镜像，2026-09-05
漏过一次——`select_momentum.py` 注册时 label 写着「一月动量（对照）」，面板
照样把 `mom_21` 印进夏普表，同一张表其余十行都是中文。镜像不会自己跟上。

闸门自己也有测试——不然它可能一直是绿的却什么都没看。加新词往 `BANNED` /
`BANNED_EN` 里写，例外进 `ALLOW` 并注明理由。

## 故意没改的

这些是 PM 本来就在用的行话，不是系统内部比喻，改了反而更远：

| 词 | 为什么留 |
|---|---|
| 净值 / 盯市 / 建仓 / 平仓 / 敞口 / 赔率 | 标准投资词汇，读者比系统更熟 |
| 全量基准 / 随机基准 | 用户 2026-09-04 拍板的口径 |
| 筛选A / 筛选B / 筛选C | 是三个**阶段**的编号，界面上每处都紧跟一个白话副标题（选主题 / 出想法 / 定持仓），编号本身承担的是「第几步」 |
| 期 / 本期 / 各期 | 2026-09-05 刚立起来的全站坐标，有专门的视图解释它 |
| σ×2 止损 / σ×3 止盈 | 有 ⓘ 释义挂在每一处 |
| 共识度 | 有释义，且它问的问题（几个组合同时选中它）本身就写在旁边 |

## 没动的东西

**数据库字段名和 book_id 前缀没改**（`paper_books`、`sel-<name>`、`book_id`）。
那是存储层，改一次要迁移历史持仓和云端两台节点的库，风险和收益不成比例。
用户说的「字段」指的是**读者看到的标签**，两者不必一致。

## 一个会再踩的坑：改代码管不了库里已存的文案

回测摘要的 note / disclaimer 是**回测当时**算好、`json.dumps` 进
`backtest_runs.summary` 的，再经 `/api/state` 直接印在证据页。改
`run_real_backtest.py` 只管下一次回测——面板会继续显示「ev_rank 臂按
exploratory 注册」。

`scripts/retag_backtest_summary.py` 按同一张词表改写已存的行。它只动展示文案：
逐行核对数字与 `inputs_sha` 未变、改完仍是合法 JSON、原值备份进
`backtest_runs_summary_backup` 并打印回滚 SQL。已在 `VACUUM INTO` 出来的副本上
验过：5 行里 2 行需改，改完残留旧词 0。

**写生产库会被 Claude 的权限分类器拦，要你自己跑：**

```
python3 scripts/retag_backtest_summary.py data/ideagen.db --apply
```

> 验完整性不能只 grep 源码——库里存的字符串 grep 源码看不见。
> 用 `curl -s localhost:8765/api/state | grep -c 臂`。
