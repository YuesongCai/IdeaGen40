# 战术 Trade Idea 排名方法论 v0.3

**用途：** 规定 1 个月 / 6 个月战术交易想法的统一排名方法，以及每次 HTML 版本必须保留的计算底稿。  
**版本日期：** 2026-07-27 HKT  
**基础版本：** `战术Trade_Idea排名方法论_v0.2.md`  
**配套文档：** `战术宏观主题评分框架_v0.3.md`

本版本完整继承 v0.2 的宏观映射、产品可执行性、三情景回报、hurdle、Opportunity Ratio 和 S / A / B / C 规则。本次新增一项强制发布规则：**每个新 HTML 版本必须同时生成一份独立、可复算、不可覆盖的 Markdown 计算底稿。**

---

## 1. 每次发布必须生成独立计算底稿

### 1.1 一版 HTML 对应一份底稿

每次重新编译或发布 HTML，都要新建一份 Markdown 底稿。旧底稿永久保留，不允许用新数据覆盖。

建议文件名：

```text
40个交易想法_情景评分计算底稿_YYYY-MM-DD_HHMM_HKT.md
```

HTML 文件名已经包含版本时间时，底稿使用相同时间。仅修改排版且完全没有改变数据、公式、产品映射或评级时，可以沿用原底稿，但必须在 HTML 版本说明中明确写出“计算未变”并引用原底稿。

### 1.2 版本绑定信息

每份底稿首页必须写明：

- 对应 HTML 文件名；
- HTML 的 SHA-256；
- 编译时间和时区；
- 市场数据截止日期；
- 产品数据截止日期；
- 宏观输入截止日期；
- 使用的方法论版本；
- 观点总数和 A / B / C、1 个月 / 6 个月数量。

HTML、计算底稿和当期输入快照作为同一个版本包保存。缺少底稿时，该 HTML 不得作为研究正式版本发送。

## 2. 每条交易想法必须记录的字段

40 条交易想法逐条保存以下内容：

1. HTML ID；
2. 具体产品、份额类别、ISIN / Olive ID / ticker；
3. 对应宏观主题、资产信号 ID、方向和期限；
4. 回报口径，固定标记为 `holding_period_total`；
5. `returnHorizonMonths`，只允许 1 或 6，并与页面期限一致；
6. 当前价格或 NAV 及日期；
7. 进入区间、止盈区间、thesis stop；
8. 中心估计的上涨 / 基准 / 下跌概率与回报；
9. 保守估计的上涨 / 基准 / 下跌概率与回报；
10. hurdle 及其无风险收益、流动性溢价拆分；
11. 中心和保守的 Expected Return；
12. Expected Gain Above Hurdle；
13. Expected Loss Below Hurdle；
14. Opportunity Ratio；
15. 最终评级及触发该评级的具体规则；
16. 产品、市场、宏观和费用数据来源；
17. 仍由研究判断决定的数字，以及相应依据。

## 3. 时间口径

所有回报和 hurdle 必须处于同一个持有期口径：

- 1 个月交易：三个情景回报均为未来 1 个月累计回报，hurdle 为 1 个月持有期收益；
- 6 个月交易：三个情景回报均为未来 6 个月累计回报，hurdle 为 6 个月持有期收益；
- 页面不得用年化情景回报与持有期 hurdle 比较；
- 年化无风险收益和年化流动性溢价必须先折算到 1 个月或 6 个月，再进入计算。

当前近似折算：

```text
持有期无风险收益 ≈ 年化无风险收益 × 持有月数 ÷ 12
持有期流动性溢价 ≈ 年化流动性溢价 × 持有月数 ÷ 12
Hurdle = 持有期无风险收益 + 持有期流动性溢价
```

正式下单前可按实际天数和复利方式更新，但三情景回报与 hurdle 必须同步使用相同期限。

## 4. 止盈、止损与情景回报的来源标签

每一个输入都要标记来源类型：

| 标签 | 含义 | 底稿要求 |
|---|---|---|
| `formula` | 由价格、NAV、收益率、duration、carry 等明确计算得出 | 展示公式、输入和结果 |
| `research_judgment` | 由宏观传导、盈利、估值、催化和风险判断形成 | 写清证据、假设和合理区间 |
| `hybrid` | 研究先确定合理目标区间，再由价格换算成回报 | 同时保留判断依据和换算过程 |

止盈点和 thesis stop 可以包含研究判断。底稿必须说明其形成逻辑，不能为了形式完整虚构公式。

当情景回报由价格区间换算时，底稿展示：

```text
目标回报 = 目标价格 ÷ 当前价格 − 1
下跌回报 = 止损价格 ÷ 当前价格 − 1
```

例如 KRE 当前价为 75.73 美元，止盈区间为 82–85 美元：

```text
82 ÷ 75.73 − 1 = +8.3%
85 ÷ 75.73 − 1 = +12.2%
中心上涨情景采用约 +10%
```

thesis stop 为 69.50 美元：

```text
69.50 ÷ 75.73 − 1 = −8.2%
保守下跌情景采用约 −8%
```

KRE 的基准情景 +3% 和 35% / 40% / 25% 概率目前属于研究判断。底稿应直接标记 `research_judgment`，并保留净息差、存款成本、收益率曲线和 CRE 拨备等依据。

## 5. 统一计算公式

```text
Expected Return
= P_up × R_up + P_base × R_base + P_down × R_down

Expected Gain Above Hurdle
= Σ P_s × max(R_s − H, 0)

Expected Loss Below Hurdle
= Σ P_s × max(H − R_s, 0)

Opportunity Ratio
= Expected Gain Above Hurdle ÷ Expected Loss Below Hurdle
```

中心估计和保守估计必须分别完整计算。底稿既保留未经四舍五入的计算值，也保留 HTML 展示值。

## 6. 发布前自动校验

每次生成新版本时，至少完成以下检查：

```text
交易想法数量 = 40
HTML ID 数量 = 40，且全部唯一
每条想法 returnBasis = holding_period_total
每条想法 returnHorizonMonths 与 1个月 / 6个月标签一致
中心概率合计 = 100%
保守概率合计 = 100%
底稿中的情景回报、hurdle、计算结果和评级与 HTML 运行时数据一致
公式复算误差不超过 0.01 个百分点
每条想法都有当前价格或 NAV 的日期与来源
每条想法都有进入、止盈和 thesis stop 的来源标签
```

任何一项失败时，先修正数据或页面，再生成新的版本时间和新底稿。
