# 问题定义：0911 对齐之后，真正卡住的是哪一件事

2026-09-19。0911 与 yifu、Jon 的对齐建议在 09-17 已经逐条落地并合表（见
`docs/2026-09-17-yifu-alignment-tracker.md`）。这份文档不重复那张表，它回答另一个
问题：**表已经全绿，为什么这套东西还不能拿去让人下判断。**

---

## 一、理想状态（把对齐会与初心合成一句）

一个 **AI 主导、PM 只做剔除** 的卫星仓：占组合 5–10 个点，与现有大主题 ETF 的
SAA/DAA 主轴并行，周度到月度短进短出，标的落在 ETF 与公募上。

它的可信度**不来自回测**。这是会上双方都同意的一点：yifu 担心每周拉的研报带后验，
我们自己也验过主题打分的样本不足。所以论证方式只能是——

> 把规则先写死、先注册，然后**让它往前跑**，用跑出来的记录说话。

这决定了整个系统的骨架：预注册（`ideagen/prereg.py`）三条假设、每条要求 **8 个
live 期次**才到期；期次分 `live`（当周实时跑）与 `backfill`（事后补跑），补跑期
不算证据。一周一期，所以可信度是**按周长出来的**，没有别的路。

## 二、现状：前半段能用，后半段没有在长

**前半段（信息收集 → 筛选 A 出主题）是真的在跑。** 09-16 那期读了 713 篇研报、
24 个主题带谱系与时点体检、29 个 RSS 早期源在收、精选五只（NLR / ARKW / …）带
四层风险透镜和行业国家穿透，卫星仓下单单可以直接打。yifu 说这一层现在就对他有
帮助，这句话成立。

**后半段——那个"让它往前跑"的记录——在 09-19 之前根本没有在长。** 三层，一层套
一层：

### 第 1 层：证据层是手动的，所以它停在了 12 天前

周跑十三个阶段里**没有回测**。喂证据页与预注册计数器的两次重放，都是人敲的命令：

| 研究 | 喂哪一页 | 最后一次运行 | 窗口截至 |
|---|---|---|---|
| `bt-real-*`（`scripts/run_real_backtest.py`） | 证据页：漏斗、排序力、稳健性、**预注册** | 2026-09-07 | 2026-09-02 |
| `bt-formal-*`（`ideagen.backtest_formal`） | 业绩页 | 2026-09-07 | 2026-09-04 |

而 09-09 与 09-16 两期**是真正的 live 期次**，早就躺在库里（`orch_runs.kind=weekly,
ok=1, data_classification=live`）。它们没进窗口，于是：

```
n_live_periods: 0        live_periods: []
prereg: ev_rank_partial_vs_vol   live_periods_since=0 / need 8   status=未到期
```

**这个 0 不是"还没开始"，是"没人去数"。** 页面看不出差别——一个从没跑过的计数器
和一个停了的计数器，读数完全一样，措辞也完全一样（"0/8，未到期"）。整套可信度
论证的进度条，接在一个人的记性上。

### 第 2 层：估值层把"读不到价格"当成了"这笔持仓价值为零"

Olive 连接器自 09-09 起每小时失败一次（refresh token 轮换后未落盘，需重新授权，
见 `olive-refresh-token-rotation`）。基金净值停在 **2026-09-09**，10 天后越过
`MAX_NAV_STALE_DAYS=10` 的陈旧线。

`sources/olive.py` 的 `mark()` 做得是对的——它返回净值**加上**陈旧天数**加上**
`usable`，注释写明"让调用方决定（并让报告披露），而不是替它猜"。

调用方没有决定。`paper.run` 的估值循环里是：

```python
m = mark_price(con, idea, d)
if not m:
    continue          # ← 这笔持仓对市值贡献 0
...
equity = cash + mv
```

于是每本账的净值凭空掉下一个坑。对账如下（`buy_all`，09-11 → 09-14）：

- 平仓 24 笔，成本 230.8 万，实现 −1.6 万（−0.7%），现金 +229.2 万 ✓ 对得上
- 但净值掉了 **47.9 万**，`n_open` 从 156 变成 **126**——平掉 24 笔，少了 30 笔
- **6 笔基金持仓无声消失**，6 × 约 8 万 ≈ 47.9 万，**正好是那个缺口**

后果不是小数点级的：

| 组合 | 修复前 | 修复后 | 该组合持仓平均收益 |
|---|---|---|---|
| ev_rank | −1.67% | **+2.50%** | +1.44% |
| buy_all | −8.07% | **+0.68%** | +0.25% |
| shortlist | −19.67% | **−0.17%** | +0.09% |
| random_pick | −15.83% | **−0.01%** | −0.15% |
| generated_ai_native | −28.14% | **−1.07%** | −0.68% |
| mom_21 | +0.89% | +0.89% | +0.18% |

`mom_21` 一格没动，因为它一只 Olive 基金都不持——这是这次修复最好的对照组。

面板头条 `books_aggregate.return_pct` 因此从 **+0.33% 显示成 −10.72%**。Jon 老板
只看 NAV，他看到的就是这个数。而同期 SPY 是 +2.81%（740.86 → 761.69）。

**注意名次也是错的**，不只是量级：修复前的排序由"哪条臂持的基金多"决定，与选股
能力无关。

### 第 3 层：第 1 层让第 2 层活了很久

如果重放每周自动跑，09-16 那天就会看到**所有臂集体跳水**——十三条臂同时掉两位数，
任何人都会立刻去对账。因为它不跑，这个数在面板上挂了一周多，没人对得上。

**两个缺陷是同一个形状**，也是这个仓里记过最多次的那一种（`ideagen-green-while-broken`、
`ideagen-read-failure-vs-absence`）：**失败返回了一个合理的值。** 计数器读 0，
净值读 −10.72%，都不是异常值，都不会触发任何告警。

## 三、今天做了什么

1. **修估值层**：新增 `paper.carry_mark()`——估值口径与成交/止损口径分开。成交、
   止损、到期仍然走 `mark_price`，陈旧就拒绝（行为**一格没改**）；估值改为按最后
   一个已知价格结转，并在 `equity` 表新增 `mv_stale` / `n_stale` / `n_unpriced`
   三列，把"这份净值里有多少是结转价"写在数据里。09-18 的 `buy_all`：13 笔、
   87.5 万（占 8.7%）按结转价计——这正是此前缺的那句披露。
2. **重算并解冻**：两个研究都重跑到 09-16。`n_live_periods` **0 → 2**，三条预注册
   假设的计数器开始走（2/8）。
3. **挂进回路**：`ideagen/evidence_sync.py` + 每日运行新增 `evidence` 阶段。只在
   落后时跑，永不抛异常（失败写进报告，不会让当天运行变 partial）。
4. **让停摆可见**（比第 3 条重要）：`evidence_sync.lag()` 进 `/api/state`，证据页
   "样本累积进度"卡头条上方加一行告警——**落后几期，就写落后几期**。自动化会停，
   停了以后说话的是这一行。

### 第一份前向证据（live 期次，n 极小，只做记录）

```
ev_rank       命中 67%   均值 +1.33%   标的×期 6
omega_strict  命中 56%   均值 +0.59%   标的×期 9
left_tail     命中 55%   均值 −0.16%   标的×期 11
buy_all       命中 51%   均值 +0.13%   标的×期 71
```

两期。什么都不能说明。**唯一的意义是这个计数器终于在走。**

## 四、剩下的问题，按"卡在谁身上"分

### 卡在时间上（唯一的真瓶颈）

预注册门槛 8 个 live 期次，现有 2 期，一周一期 → **约 2026-11-11 到期**。中间没有
捷径：补跑不算证据，这是当初自己定的规矩，也是 yifu 担心后验时我们给的答复。

**这意味着未来六周的工作重心应该是"别让期次丢"，而不是再加功能。** 一期丢了就是
一周，且不可补。已知丢过：08-05（漏跑）、09-16（每日运行被 OpenD 卡死 17 小时，
已修）。

### 卡在用户身上（一句话就能解掉，解不掉就一直烂着）

| 事 | 拦住了什么 | 怎么解 |
|---|---|---|
| **Olive 重新授权** | 基金净值停在 09-09；8 只基金 09-02 的成交可能带前视，无法离线核对；每天多一笔按结转价计的持仓 | `ideagen olive-auth` 走一次 |
| X / Reddit 凭证 | 早期信号腿只剩 Substack RSS；"抓源头不抓扩散期"这条只做了三分之一 | `X_BEARER_TOKEN`、Reddit OAuth |
| 主题周报飞书群 ID | yifu 要求的"每周看筛选 A 输出"只能登展示节点看，推不到群里 | 给群 ID |
| 谱系两对待审 | 同一叙事换名归并差最后一步人工确认 | `ideagen theme-lineage` 看两对 |

### 卡在设计上（对齐会点了名，但还没有答案）

1. **"主题能找出哪里放波动"——这是整套东西的第一原理，至今没有被证明。** 现有
   3 期走满，`vol_ratio_log_dm` 差值 +0.038，区间 [−0.14, +0.23] **盖住 0**；
   争议度与放波动的秩相关 ρ=0.17，区间也盖住 0。样本不足，不是证伪，但也**不能
   拿去当卖点**。这条和预注册一样，只能等期次。
2. **赛马的阶段性问题没有解。** yifu 说赛马跑赢的像"卖过去三年最牛的基金"。WS-E
   给了市场阶段框架（MTUM/SPY），但各格样本都不足，且这是一个**需要跨越多个市场
   形态才能回答的问题**——比 8 期还远。诚实的说法是：**筛选 C 现在不该重**，前端
   给 PM 蒸馏方向就好，这也正是 yifu 的建议。
3. **PM 复核用了零次。** `shortlist.reviews: []`。Allspring 结构里"人做反方"是
   核心，代码全在（只剔除不塞名字、四层透镜、否决理由入库并回流成准则），但**从
   来没有人用过一次**。一个没人用的闭环，和没写是一样的——这是本仓的老毛病
   （`panel-designed-but-never-wired`）。这件事不需要写代码，需要一次真实的复核。

## 五、一句话

> 前半段（主题）已经能用，且 yifu 认可；后半段的可信度**只能按周长出来**，而在
> 今天之前，那个记录它长了多少的计数器停了 12 天，量它长势的那把尺子（净值）又
> 把一次连接器故障读成了 −10.7% 的亏损。两样都修好了，也都挂进了回路、并且在停
> 摆时会自己喊出来。**接下来六周最该做的事，是保证每个周三都跑成，以及让 PM 真
> 的用一次复核。**
